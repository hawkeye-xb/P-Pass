# 产品体验差距讨论留档（2026-08-04）

> 产品 session 工作档，非工程交接件（工程交接见 NEXT.md）。
> 背景：M2 收官、H-10b 核心链路已用正式产物走通、全家狗粮周将启。
> 结论状态：清单已过一轮逐条讨论，用户裁决已记录；卡片候选池待逐个细化。

## 〇、目标体验（锚）

> 家人拿到手机，扫一次码，之后**什么都不用做**；任何时候打开 App，
> 都能得到「照片安全吗」的真话；家里任何一端都看得见「谁备份了什么」；
> 想看回忆时，时间线是个能翻的家庭相册。
> ——设备叫「妈妈的手机」，不叫 NodeId。

总纲（用户点题）：**简单 ≠ 黑箱。默认自动挡，但给三层掌控权**——
1. **看得见**：状态真话、传输两端可见、连接路径可见；
2. **可干预**：暂停、取消、范围选择、设置、任一端可单方停止；
3. **可查账**：活动记录（审计日志人话化）。

目标体验的量化锚在 gate 里：M2 gate =「全家狗粮一周，100% 备份完成率」，
M3 gate =「5-10 户私测两周」。M4 本身只有官网+发帖+止损线。

## 〇之二、数据铁律（用户裁决 2026-08-04，底线级）

> **数据不上云，不进我们任何库。relay 只是中转传递的兜底。**
> **数据隐私是底线。** 多活备份（多远端冗余）后置，届时再谈备份的备份。

按三条数据平面落实边界：

| 平面 | 内容 | 边界 | 现状核对 |
|---|---|---|---|
| **内容面**（照片/文件字节、缩略图、文件名、hash、时间线） | 只存在于用户自己的设备之间 | 永不落我们任何基础设施；relay 仅转发 E2E 密文、不落盘不解密 | ✅ 架构即如此 |
| **寻址面**（rendezvous：节点身份+地址） | 帮设备互相找到对方 | 只存加密身份与网络地址，**不得携带任何内容元数据**（文件名/hash/数量） | ⚠️ 待审计项：OPS-01 部署前核对 rendezvous 存储字段 |
| **遥测面**（匿名运行事件） | 四事件字典、匿名 ID | **用户内容与可识别信息永不入内**（照片名/hash/设备名/库规模明细均禁止）；enabled=false 零网络已实证；privacy 页如实枚举字段 | ⚠️ 待审计项：OPS-01 部署前逐字段过一遍事件字典 |

推论两条：①狗粮周完成率度量**以家内 IPC 水位为主**（§三之四 第 6 条，
数据不出家门），遥测只作匿名聚合补充；②privacy 页文案 = 这张表的人话
版，开源仓库即审计通道——叙事不用写，照实翻译即可。

## 一、差距清单 v1（首轮，按紧迫度）

1. **备份状态说的是「这一次」，不是「真话」**——状态药丸只反映本次会话，
   重开 App 归零；目标：恒真三元组「手机 N 张 · 已备份 M · 待备份 K +
   最后成功时间」（= M2 gate 的用户侧度量面）。
2. **反馈链单端**（Tailscale 教训）——手机备份成功只有手机知道，
   Mac 端无存在感。铁律：一切传输两端可见。
3. **网络心智模型泄漏**——「Reconnect」手动按钮、Trouble 裸错误文案、
   「unreachable + raw error」。目标：断连自动重试，状态用人话说下一步。
4. **时间线是缩略图墙，不是家庭相册**——视频缩略图灰块（daemon
   thumb_state=2 已知债）、计数显示已加载数而非库总数、预览只有 1024、
   无保存/分享/导出。
5. **「拿回来」闭环不存在**——无存回手机/导出原图/新手机恢复入口。
   备份产品的最终承诺是恢复。
6. **「家人」概念在 UI 里不存在**——authz 有角色，但时间线不区分谁拍的，
   设备列表偏设备而非人。
7. **Mac 是相册的家却看不了相册**——桌面只有托盘+向导，照片只能 Finder 翻。
8. **正向反馈只有绿点，没有「值得」的时刻**——ConnInfo 未翻译成人话；
   「你的 3,000 张照片安全地住在家里的 Mac 上」这种时刻没有表达。

## 二、逐端讨论（用户实测反馈 × 代码事实核查 × 产品答案）

### 事实核查（反直觉的三条）

- **「已直连」是假话**：`diag_agg.rs` 里 `OnlineDirect` 是状态机中性默认值，
  daemon 活着就显示「已直连」，不度量任何连接、不知道和谁连。
- **`folder.set` 什么都没改**：MVP 实现只写配置、`applies: "on-restart"`、
  永不迁移已有照片；UI 只回「已保存」，两个坑都没告知。
- **后台备份已完整但隐形**：每 4h 周期任务（充电+非计量 WiFi，熄屏可跑）+
  打开 App 补跑 + 批次期间 FGS 静默通知。慌的原因不是没做，
  是规则没有任何一处告诉用户——零设置页、零说明。

### 双端共通

- **连接路径透明**：技术事实=iroh 端到端加密，**relay 只见密文**。
  每设备行显示「直连 ✓」或「经中继转发 · 内容加密，中继无法读取 ·
  速度受限」；首次走 relay 给一次性说明。「ping 通但直连不了」即
  「经中继」态，无需第三种状态。ConnInfo 数据已有，缺翻译层。
- **任一端可单方停止（裁决 2026-08-04）**：连接的任何一方都能随时
  单方面终止，无需对方在场——否则数据安全无从谈起。桌面已有
  「停止后台服务」+ revoke 设备；**移动端补**：「暂停自动备份」全局
  开关 + 「断开与这台电脑的连接」（解除配对）。

## 三、移动端「备份透明度 + 统一时间线」设计（已收敛 2026-08-04）

先例调研结论：主流产品（Apple 照片/共享图库、Google Photos、Immich、
Synology Photos）**都不做两个并列时间线**，一律是「一条时间线 + 范围
过滤器」。两视图初案作废，按用户裁决改统一视图。

### 备份页（现 Backup tab）

- 恒真三元组：**手机 1,234 张 · 已备份 1,180 · 待备份 54**（持久状态，
  非会话态）+ 最后成功时间。**分母 = 已选备份范围内的照片数**。
  点「待备份 54」→ 网格预览（只是可见性，不阻塞自动挡）。
- 进行中：当前项缩略图 + 进度 + **暂停**（幂等管线使暂停/续传天然安全）。
- 失败区：失败清单常驻（有失败才现），可重试、原因人话；
  失败通知点进来落在这里。成功永远沉默。
- 底部规则一行（「插电+WiFi 自动备份」）+ 设置入口
  （备份相册范围/仅充电/仅 WiFi/暂停自动备份/断开连接）。

### 照片页：统一时间线（裁决：统一视图，归因信息按需出现）

- **一条时间线**合并三源（BLAKE3 去重）：本机照片、我已备份的
  （合一）、家人设备备份的。本机有的读本地缩略图（秒开）。
- 顶部轻量过滤器（Apple 共享图库式）：**全部 / 仅本机 / 按家人**。
- 「谁拍的」按需出现：网格不标来源；大图页显示「来自 妈妈的手机 ·
  7月31日」；按人看走过滤器。
- 角标（裁决：成功不标）：未备份 `↑`、失败 `!`、
  仅在电脑（本机没有）= 轻角标，兼作**「保存到手机」**取回入口线索。

### 备份范围（裁决：需要，抄 Google Photos 作业）

- **默认只备份「相机」（DCIM）**，截图/微信/下载默认关；
- **配对完成后第一个页面 = 相册选择步**（相机默认勾选，其余可见但关）
  ——产品第一次开口就说「我只拿你明确给我的」，信任建设 + 防
  「上来就捞一堆」+ 方便测试（勾小相册跑全链路）；
- 设置页每相册一开关，随时改；三元组分母随范围走。

### 状态判定机制（一句话工程边界，不展开）

增量扫描+BLAKE3（备份管线已有）→ 与远端批量 exist-check
（复用 manifest「给 hashes 回 missing」语义，只查不传）→ 本地状态缓存。
离线时时间线用缓存状态照常显示，远端来源项给不可达提示。

### 不做（本期）

编辑、相册管理（指整理功能，范围选择除外）、人脸/搜索、多远端。

### 家人照片默认可见性（裁决 2026-08-04：C）

统一视图下配对即全家照片互见。**裁决 = C**：全家共享池起步（狗粮周
自家够用），桌面管理端设备粒度可见性开关（owner 控制）后置——权限
控制有真实需要，但不是现在。落点：桌面壳信息架构改版卡的设备管理页。

——至此 §三 全部收敛，无遗留拍板项。

## 三之二、差距⑨：常驻服务自律（2026-08-04 现场发现）

用户本机历史累计 ~10 个孤儿 daemon；当场诊断存活 4 个，两类病：

- **A 类·测试脚本泄漏（3 个）**：8/3 同一脚本起的抛弃式 daemon（PPID=1、
  随机端口）未收尸——随机端口防撞的副作用是永不被发现。
- **B 类·版本漂移孤儿（1 个，值班中）**：launchd 的 `com.p-pass.daemon`
  指向 7/31 开发构建路径（`src-tauri/target/.../ppf-daemon`），占着
  UDP 41145 与设备身份；8/4 正式 dmg 只有托盘接管，**正式 daemon 从未
  上岗**。⇒ H-10b 桌面侧结论需打补丁：托盘正式、服务是旧开发版。
  普通用户每次升级都会复制此病。

原则（前辈模式）：**常驻 = 对用户资源的特权，必须自证纪律**。
1. **单实例锁**：IPC socket 排他绑定即锁（Tailscale/Docker/Dropbox 模式），
   绑不上即退出；
2. **唯一生父**：只有 launchd/systemd 允许 spawn daemon，托盘/向导/CLI
   一律 kickstart，绝不直接 fork；
3. **抛弃式随父死**：daemon 提供 ephemeral 模式（stdin EOF 即退），
   脚本 trap 只是第二道保险；
4. **升级退位**：plist/unit 指向稳定路径；新实例发现锁被占 → IPC 版本
   握手 → 旧实例优雅退位（newest wins）。UPD-01 搁置 daemon 自更新
   可以，「旧 daemon 退位」不可一起搁置；
5. **资源自律 + 可观测**：ProcessType=Background、idle 零轮询
   （FSEvents 非扫描）；status 报自身 PID/版本/路径/启动时间，托盘
   显示版本，多实例/版本不匹配是一等状态；daemon 启停进活动记录。

## 三之三、上层产品议题（2026-08-04 提出，待逐个讨论）

体验差距靠狗粮能穷尽，以下五题不能——需要自上而下想清楚：

1. **狗粮周的验收剧本**（最紧迫，开跑前定）：M2 gate =「100% 备份
   完成率」，但谁、在哪、怎么读这个数？三元组 UI 未落、遥测未部署
   （OPS-01 待派）。需定义：每台设备每天看什么、异常如何上报
   （logs.export 路径）、周末以什么证据判 gate 过/不过。
   不定义,狗粮周只能得出「用了一周没炸」的模糊结论。
2. **恢复承诺 = 第二次关键时刻**：备份产品的死穴是用户只在灾难时
   发现备份没用。三个故事要有答案：①换新手机（恢复流程）②手机
   丢了（同上+吊销）③**家里 Mac 磁盘坏了**（单点故障——多远端
   后置期只能给诚实 FAQ）。私测必被问。
3. **双角色产品人格**：安装者（管理员）≠ 使用者（家人）。升格为
   设计原则：每个功能先问「给管理员还是给妈妈」。也是增长路径：
   r/selfhosted 抓管理员 → 管理员发展全家。
4. **信任与安全叙事**：差异化即「数据不出家门」。需一页人话版威胁
   模型（E2E、relay 只见密文、我们运营/不运营什么、遥测收什么、
   不在大陆运营端点）。M3 评审抓过「安全声明夸大」——诚实本身是
   叙事的一部分。私测时就该给受测家庭看。
5. **kill line 的信号定义**：已约定「3 个月无指数信号即停」，但
   「信号」未定义。发布前定：什么算数（周活家庭/自然安装/转化）、
   在哪测（遥测哪几个事件）、多少算指数。不定义的止损线等于没有。

另：第二场景时机（引擎通用于任意文件已裁决，何时开文档/其他文件
备份）归开放议题，避免过早泛化。

**降维裁决（用户反馈后收敛）**：五题中仅 1、2 真正弯折当前设计
（落入 §三之四）；3 = 设计口头禅（每功能先问「给管理员还是给妈妈」）；
4 = privacy 页 + 开源本身即叙事，M4 文案活；5 = 运营纪律，发布前定。

## 三之四、面向变化的架构预留（2026-08-04 收敛）

原则：**不为未来施工，只在反正要新建的地方把缝留对**。M3 大卡细化时
逐条核对。

1. **可见性（裁决 C）→ 协议语义**：`timeline.page` 返回语义今天定死为
   「你可见的」（proto 注释即可），客户端永不做权限判断、不假设拿到
   全库。将来开关 = daemon query 过滤一处改，两客户端零动。
2. **备份状态缓存 → key 带远端**：新建状态表用 `(hash, remote_id)`；
   凡属配对关系的状态（pairing/watermark/状态缓存/缩略图缓存）收进
   **per-remote 目录**——「切换远端重建」= 删目录，原子。
3. **相册选择 → 概念叫「备份来源 sources」**：实现=MediaStore bucket，
   UI 才叫相册；第二场景加 source 类型即可。时间线渲染留未知
   media_type 兜底卡片（文件名+图标）。
4. **统一时间线合并层 → 远端流 × 本地流运行时 join**，不物化第三份库；
   可见性/多远端/范围变更各只动一侧。
5. **取回 → 可恢复队列语义**（暂时队列长度=1）：与备份同骨架
   「清单→缺什么→传什么→幂等续传」反向用；换新手机整机恢复 =
   同队列灌整清单。
6. **狗粮周度量 → 桌面 status/IPC 加 per-device 备份水位**（audit 数据
   已有）：agent 每日拉全家状态（符合 agent 优先接口铁律）；同一份
   数据即活动记录页与「两端可见」的数据源，一鱼三吃。
7. **桌面壳零业务逻辑铁律保持**：M3 改版前新功能不往单页壳堆交互
   逻辑，新页面按分页信息架构立卡。

## 三之五、第二轮收敛：哨兵机制、多品类、命名、狗粮周压缩（2026-08-04）

**a. 沉默失败 = 产品最大死亡场景**（自动备份第 3 周静默停摆，灾难日才
发现）。机制 = **互为哨兵**（看门狗不能住在被看的东西里）：
- 手机死 → daemon 侧发现设备水位 N 天未推进 → 桌面亮红「妈妈的手机
  5 天没备份了」，修复动作=去该手机开一次 App（catch-up 自动补）；
- daemon 死 → 手机侧发现远端 N 天不可达 → 提示。**通知节流（裁决）**：
  状态常驻页面、系统通知首次即发 + 之后最多 72h 一次 + 恢复静默清除；
- 两端全死 → 承认边界，「可预期」承诺一句话：**只要家里电脑开着、
  手机插电连 WiFi，备份就在发生；任何一边不对劲，另一边 X 天内亮红**。
  （用户原则：可预期 > 功能强。）
- **桌面亮红的死角（用户指出）**：狗粮机不一定每天有人看屏幕 →
  运维端方案进开放议题（见 §四），不急但重要。

**b. 多品类（裁决：单品类图片先行，不用考虑太多）**：存储端引擎已
通用，品类差异只发生在**浏览层**——媒体=时间线、文件=证据列表，两种
浏览形态封顶。现在唯一多花心思处：**备份页 IA 按「来源」分组**（顶部
全局三元组 + 每来源一行自己的三元组），将来微信目录/任意文件夹 =
列表加一行零改版。to-agent 接口靠后（daemon 侧本就 agent 可驱动）。

**c. 设备命名（裁决）**：设备自报名（手机名）默认 + 移动端可编辑 +
**桌面管理端加备注**（「妈妈的手机」本来就是管理员视角），显示规则=
备注优先、fallback 自报名。

**d. 时间线定位 = 证据浏览器**：让用户确认「照片安全、拿得回」，
不是日常翻照片的地方（那是系统相册的仗）。此定位是时间线投入上限的
挡箭牌（搜索/回忆/编辑一律用它挡）。

**e. 狗粮周压缩（裁决：必须压缩，没有这么多个狗粮周）**：故障注入换
日历时间 + 夜间 8 小时是主战场（插电+WiFi+熄屏=触发条件本身）+
设备日换日历日 + 与 M3 滚动衔接（自家稳定 3-4 天即邀首批 2 户）。
Case 清单与三晚编排：**[dogfood-week-cases.md](dogfood-week-cases.md)**。
Gate 语义修改建议见该文件（≥20 设备日+注入全绿+范围内 100%+零 P0）。

**f. 狗粮周前小卡（裁决：全保留，agent 时代写需求便宜，大胆点）**：
分两档——**阻塞项**（不落狗粮周作废）：B 类孤儿修复、三元组+per-device
水位、ROM 白名单引导；**尽量项**：其余十张，能落几张落几张不阻塞开跑。
