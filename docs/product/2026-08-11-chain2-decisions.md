# 链 2 产品讨论定案（2026-08-11，用户 × 验收人）

> 六个议题 + 四轮深挖的全部裁决。下一批卡（RET-01/SENT-01/DOG-02b/
> DESK-04/NAME-01）以本档案为语义基准。

## 产品定位（用户原话级，README/对外口径按此写）

**数据隐私、个人 NAS 式数据备份**。目前只针对图片；运行稳定后按类型
逐个做到位（文件等）。不做相册管理器、不做编辑器、不做云。

## 裁决清单

### ① 取回 = 单张「使用」动作，批量恢复后置

场景推演（频率排序）：A 删了本机照片后来要用（高）；**B 想要家人拍的
照片（高，本产品与网盘的差异化核心）**；C 拿原图去修图（中）；
D 换机/丢机整库恢复（极低频但意义时刻）。

- **MVP**：查看页两个动作——「保存到相册」（写 MediaStore，覆盖 A/B）
  + 「用其他应用打开」（系统分享面板，覆盖 C）。
- **防循环已论证**：存回相册的照片被再次扫描 → hash 相同 → 幂等去重
  为零，不会循环备份。
- **D 后置**：独立「恢复向导」卡进 ROADMAP，不在本批。

### ② 设备即人；改名 = ID 与显示名分离

不做人的映射/标签。审计只记 node_id（稳定），显示名是 device 表一列，
改名写 `device.renamed` 审计（旧名→新名）。改名卡 L0 排队尾，可砍。

### ③ 查看器维持「证据浏览器」；编辑不做、结果回流

原图不可变（内容寻址，hash=身份）是产品承诺——「改原图」操作不存在，
用户担心的「我改了家人看到变了」架构上不可能。编辑走外部 App
（「用其他应用打开」），编辑结果存相册后由自动备份作为**新照片**回流。
我们不做任何编辑功能。

### ④ 电池白名单不进 onboarding；改契机式提醒

常驻引导卡片保留（DOG-02 现状）。新增：**该跑没跑成时才提醒**——
夜间自动备份连续 N 次未能执行 → 通知「昨晚没备份成，可能是系统限制
了后台，去加个白名单」。出问题的时刻提醒比空泛建议有说服力。

### ⑤ 互为哨兵补手机侧；机制=搭便车不是心跳

目的：**备份静默失败时用户必须知道**。桌面盯手机已有（>5 天哨兵红）。
手机盯电脑：不做后台心跳（耗电红线）——**搭现有后台任务的便车**
（周期兜底/新照片触发跑的时候顺记 daemon 可达性），连续 3 天全部
触发都不可达 → UX-02 通道通知：「3 天没连上电脑了——照片没丢，
去看看电脑上的 P-Pass 还开着吗」。与 PRES-01（前台心跳，管桌面显示
手机在线）分工互补。

### ⑥ 桌面向导不重做，低成本对齐

T-042 三步向导保留流程，只做：文案按产品语言过一遍 + 视觉 token 化 +
二维码步接新配对弹窗流。

托盘太小，有关键辨识度即可，不追求闪电细节。候选对照存
docs/design/2026-08-11-icon-v1/drafts-gallery.html 托盘区。
