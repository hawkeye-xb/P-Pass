# 修复验证：#1246 服务版覆盖安装后 App 退回首启向导（2026-10-28）

> 对象是 [test.15 应用内更新验证](2026-10-28-update-windows-v0.10.0-test.15.md) 发现的 #1246。修复在分支 `fix/1246-config-acl`。验证只用电脑（IPC、UI Automation、日志），没有用手机。两次覆盖安装合在一个提权脚本里，只点了一次 UAC，其余由 agent 完成。
>
> **结论：修好了。** 在 test.15 现场（config.toml 的 Users 只读已被冲掉，App 卡在向导）上覆盖安装新包，App 直接进主界面；同一个包再覆盖一次，结果一致。两次都是 daemon 先补授，App 后启动，没有遇到竞态。

## 根因与修法

- **根因**：窗口程序靠 config.toml 判断「配过没有」。服务形态下目录私有，config.toml 的 `BUILTIN\Users:(R)` 只由 daemon 在写库位置时授一次（#1238，`LibraryLocation::set`）。安装器升级时执行 `icacls "%ProgramData%\P-Pass\*" /reset /T`，把子项重置成只继承父目录，然后只给自己负责的 `wanted-state` 补授，config.toml 的授权就丢了。
- **修法**：常驻 daemon 每次启动、加载 config 后，config.toml 存在就幂等补授一次（`LibraryLocation::reshare_config`，`main.rs` 调用；沙盒和未配置都不碰）。授权仍只在 daemon 一处，安装器 reset 或手动 icacls 冲掉之后，下次启动就会自愈。授不上只告警、不阻断启动。安装器不改。

## 竞态

壳只在启动时判断一次「配过没有」，daemon 补授在服务启动后约 0.5 秒。两次都是「安装器起服务 → daemon 补授 → 安装器退出 → App 启动」，补授比 App 启动早 0.72 秒和 0.95 秒。这个先后不是结构保证的（`sc start` 不等服务就绪），但应用内更新时 App 也是在安装器退出后才重新打开，所以实际路径和本次测的一样。本轮没有撞上竞态。
