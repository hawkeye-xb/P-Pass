# DESK-11 手机主动断开配对后，桌面审计里的名字变回了 id　级别 L3（backlog）

> 🔵 状态：backlog（验收人 2026-08-26 明确「这块需要确认，开 backlog」）

## 问题

验收人反馈（2026-08-26 真机 0.4.0-test.8，回归步骤 #13）：

> 「小瑕疵，desktop 的审计对应名称，在 mobile 端主动断开之后，好像展示了 id，
> 这块需要确认。」

## 要先确认的（现象本身还没坐实）

1. 复现：手机端主动断开配对 → 桌面「活动」/审计列表里那几行的设备名是否
   从「三星 SM-S9210」之类变成一串 hex。
2. 如果是：**是名字丢了，还是名字本来就没存进审计行**？审计行大概率只存
   `device_id`，展示时去 `devices` 表 join 出名字；设备行被删之后 join 不到，
   于是回落到显示 id。
3. 如果确认是 join 失败的回落——正确行为是什么？审计的意义是「事后能看清
   发生过什么」，那么**断开配对不该让历史记录失去可读性**。可能的出路：
   审计行落盘时就把当时的设备名一起写进去（快照，而不是引用）。

## 与已知项的关系

- `DESK-10` 刚给 `audit.detail` 里的长 hex 加了掩码（前 8 位 + `…<masked>`）。
  如果这次看到的 id 是**完整**的 hex，那说明设备名那一列走的是另一条路径，
  没过 `scrub()`——那就不只是可读性问题，还是一处脱敏漏。**先确认这一点。**
