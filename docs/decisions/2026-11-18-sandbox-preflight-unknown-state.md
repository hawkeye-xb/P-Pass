# 沙箱预检的「未知」不许写成「已起来」：超时三态化，不进成功缓存

- 状态：已采纳
- 日期：2026-11-18
- 采纳：产品负责人 2026-11-18 拍板「做」（方案见 [#1312 评论](https://github.com/hawkeye-xb/P-Pass/issues/1312)）
- 关联：#1312（本方案按它实现）、#1300（首发现场：2026-11-02 交卡时 `isolated_preflight` 偶发红）

## 背景

macOS 上每个解码 worker 首次拉起前要过一道沙箱预检（`crates/platform/src/isolated_unix.rs:159`
的 `preflight`）：用生产 Seatbelt 策略空跑一遍 worker，证明「沙箱 + 这个 worker 加得起来」。
预检最多等 5 秒，之后 SIGKILL。现在的行为是**超时也被当成「已起来」**：

- `isolated_unix.rs:183-190`：超过 5s → `libc::kill(-pgid, SIGKILL)` → `break None`（拿不到退出状态）；
- `isolated_unix.rs:192-200`：「被信号杀 / 65 / 71 退出」才算没跑起来，这段判定包在
  `if let Some(st) = status` 里，`None`（超时）根本进不来；
- `isolated_unix.rs:201-204`：`None` 一路落到函数末尾，被 push 进 `OK` 成功缓存并返回 `Ok(())`。

类型层面同谋：`crates/platform/src/isolated.rs:83` 的 `spawn_isolated -> io::Result<IsolatedChild>`
**没有「未知」这个值可表达**，作者必须在返回处二选一，当时选了乐观。

### 复现（确定性，不靠造高负载）

用真二进制（clang 编的 `sleep(6)` 程序；脚本会被沙箱直接拒掉，走不到超时分支）调
`platform::isolated::spawn_isolated`，在 `origin/main` 的隔离 worktree 里得到：

```
[repro] 第一次调用：ok=true 耗时=5006ms
[repro] 第二次调用：ok=true 耗时=0ms
test preflight_timeout_must_not_be_reported_as_healthy ... FAILED
```

第一次卡满 5 秒期限照样返回 `Ok`；第二次 0ms——预检被跳过，用的是那次「未知」写成的成功缓存。
复现用例在 `/tmp/ppass-1312-repro/crates/platform/tests/zz_repro_preflight_timeout.rs`（只在本机，不进仓库）。

### 影响

- 测试层：`crates/platform/tests/isolated_preflight.rs` 的
  `preflight_separates_not_started_from_started` 在高负载下偶发红（SIGABRT 触发系统崩溃报告，
  worker 退出慢于 5s → 超时 → 误判「已起来」→ 断言红），#1300 现场正是 5.02s 耗时 + load ≈ 8.7。
- 产品层：高负载时被沙箱拦住而 abort 的 worker 被预检判成「已起来」，解码失败被归到
  「这张图坏了」，而不是「本机沙箱系统性失败，要重试」——一次超时对整个照片库生效且永不重试。

## 决定

1. **预检返回值三态**：`preflight` 的结果能表达「成功 / 沙箱明确拒绝 / 未知（超时）」。
   实现上平台层返回类型从 `io::Result<()>` 换成能区分三态的枚举（或以独立错误类别承载「未知」），
   `isolated.rs` 的 `spawn_isolated` 对外签名按需要跟着调。
2. **超时不写 OK 缓存**：只有「预检真正证明能跑」（正常退出）才进成功缓存；
   「沙箱明确拒绝」返回失败（上层记系统性失败，可重试）；「超时」返回未知，
   **不写缓存**，下次调用重新预检。
3. **两条失败路径分开走**：「沙箱明确拒绝」（被信号杀、sandbox-exec 报 65/71、sandbox-exec 缺失）
   与「超时未知」对上层是不同的错误，调用方对「拒绝」可以直接判本机系统性失败，
   对「未知」重试；上层 `crates/media-codec/src/sandbox.rs:145` 现有映射
   （spawn 错误 → `CodecError::SandboxUnavailable`，本机系统性问题，不把照片标成坏图）保持不变。
4. **确定性测试**：`sleep(6)` 的假 worker（真二进制，clang 编译）必须拿到「未知/失败」，
   不得返回 `Ok`；覆盖「超时 → 不进缓存 → 下次重新预检」这条分支。

## 理由

**这件事本质上要保证什么**：预检的意义是「证明沙箱能跑这个程序」。证明不了就不能宣称能跑；
但「太慢」不等于「被拒绝」——拒绝是结论，太慢是没有结论。把没有结论写成肯定结论，
错误就永久化了：一次误判写进缓存，对整库生效且不再重试。

**标准做法**：探测类检查的结果是三态（成功 / 失败 / 未知），未知不落确定性缓存、走重试路径，
并把「明确拒绝」与「未得出结论」分开报。这也是幂等性健康检查的通行语义（探活失败与探活超时分开）。

**我们怎么对齐**：现有出口已经对——上层把预检失败映射成 `CodecError::SandboxUnavailable`
（本机系统性问题），不会把照片标成坏图；所以「不宣称成功」不会造成硬停摆，只是让失败被
归到正确的桶里。要改的只有平台层一处：让类型容得下「未知」，让超时不进缓存。

## 后果

- 高负载下 worker 预检超时不再被记成「可用」：下一次调用会重新预检（代价是慢一档的路径
  可能多等一个 5s 期限），换来的是不再把「不知道」永久写成「没问题」。
- `preflight_separates_not_started_from_started` 高负载偶发红的触发条件（预检超时）从根上消除。
- 验收按红 → 绿 → 撤销回红给原始输出：
  红 = 复现输出（`ok=true 耗时=5006ms`、第二次 `0ms`、断言 FAILED）；
  绿 = 修复后同一用例拿到「未知/失败」；撤销修复 → 回到红。

## 备选

- **在旧 `if` 上加判断（`None` 也判失败）**：不选。它把「太慢」和「被拒绝」混成同一种失败，
  调用方无法区分「本机沙箱坏了」和「这回太慢了」；而且类型里还是没有「未知」，下次有人
  碰这段代码还得在同一个二选一里再赌一次。超时与拒绝语义不同，就该是不同的返回值。
- **简单 fail-closed：超时一律判失败、且失败也不重试**：不选。方向对（不再宣称成功），
  但把「没有结论」当终局结论同样错：本机只是暂时忙，一次超时就永久拒绝这个 worker，
  高负载机器上的照片库会被无谓地判成系统性失败。未知要可重试。
- **把 5s 期限调大或做成指数退避**：不选。期限多长都有被压过的时候，问题不在期限长短，
  在超时后的归类；调大期限只是把误判的触发条件往后挪。
