## 测试步骤（每场景）

1. 桌面端启动 iroh-probe CLI 监听：`cargo run -- listen`
2. 手机端打开 Android Probe App，填入桌面 NodeId
3. 点击「Connect + Send 100MB」执行 20 次
4. 每轮自动记录：path（lan/direct/relay）、rtt_ms、throughput_mbps、error（如有）
5. 用 UidtLogger Share Log 导出 JSONL 文件
6. 汇总填入上表

## 判定标准

- **绿（通过）：** 同 WiFi 直连率 100%；家宽↔蜂窝直连率 ≥70%
- **黄（观望）：** 家宽↔蜂窝直连率 50~70% → relay 兜底可用但需评估体验
- **红（回退）：** 同 WiFi 直连率 <100% 或家宽↔蜂窝直连率 <50% → 排查 iroh 配置/网络环境

## 额外变量（发现即记录，不限场景数）

- 手机锁屏后连接是否中断（ForegroundService 测试，附带）
- 网络切换（WiFi→蜂窝）中传输是否恢复
- NAT 刷新：保持连接 30 分钟不动，能否继续传

## 归因修正（2026-07-29，基于家侧网络画像 + ticket 解码 + App 代码审查）

### 触发点：一个不可能成立的矛盾
家侧 agent 实测：监听端所在 VM（UTM NAT 模式，192.168.64.3）**没有全局 IPv6**（仅 link-local，v6 出网不通）。
而场景 7 记录为"20/20 direct 全 IPv6"——两者不能同时为真。

### 根因：App ipver 分类器缺陷（App 第五缺陷）
`IrohProbe.kt` 用 `remoteAddr.contains(":")` 判 v6，而 `ip:port` 字符串必含冒号 →
**v1/v2 APK 所有日志的 `ipver` 字段全部不可信（所有 direct 一律记成 v6）**。
v3 已修复（剥离端口后按 host 判断），并新增 `remote` 字段记录真实对端地址供事后核查。

### 证据链：家侧监听端 ticket 解码（2026-07-28 的实际 ticket）
- 直连地址：`123.119.22.188:46xxx`（北京联通**真实公网 v4**——并未被代理污染）+ `192.168.64.3`（VM NAT 内网，坐实监听端在 VM 里）
- **不含任何 v6 地址**；relay 分配 usw1（LA）——relay 的 HTTPS 注册被 Clash 代理到 LA 出口，但 UDP 地址发现拿到的是真实 WAN

### 家侧网络画像（家侧 agent 采集，2026-07-29）
| 层 | 事实 |
|---|---|
| 宿主机 Mac mini | macOS 26.5；en0 192.168.1.6/24；**有全局 v6** 2408:8207:5455:ef60::/64（联通 PD/SLAAC）；**Clash Verge (Mihomo) TUN fake-ip 全局代理**，v4/v6/DNS 出口均为 LA 38.49.42.238 |
| VM（监听端所在） | UTM/QEMU **NAT 模式**，192.168.64.3/24；**无全局 v6**（v6 出网不通）；v4 出站经宿主 Clash TUN |
| 路由器 | ASUS（ASUSWRT）；**UPnP/NAT-PMP 关闭**；IPv6 PD 已下发；WAN v4 与 v6 入站防火墙策略**待登录确认** |
| STUN | 被 Clash TUN 劫持（fake-ip 连 DNS 都接管），宿主/VM 均无法直接测 NAT 类型 |

### 结论改写
1. **场景 7 的 20/20 direct 实际是 v4 打洞，且穿过了【ASUS NAT + UTM vmnet NAT】双层 NAT**（UPnP 还是关的）
   ——比原结论信息量更大：办公 WiFi → 家宽双层 NAT，v4 打洞 100% 成功、16.9 Mbps 稳定。iroh 的 v4 打洞能力被低估了。
2. **"IPv6 是国内直连率的决定性因素"作废**，降级为待验证假设（见上方对照实验标注）。
3. **场景 2（5G→家宽 0/20 direct）嫌疑收敛**，按优先级：
   ① 蜂窝侧 CGNAT/对称 NAT 与家侧双层 NAT 的组合打洞难度（办公 WiFi 的 NAT 友好得多）；
   ② Clash TUN 对打洞 UDP 流的干扰（改写/重路由部分流量）；
   ③ 路由器 UPnP 关闭（少一条端口映射逃生通道）。
   ~~"v6 打洞被蜂窝防火墙拦截"~~ 作废——当时不存在 v6 路径。
4. relay 兜底的 11.3 Mbps 含 Clash 绕道 LA 的开销，**国内自建 relay 的 A/B 对比价值上调**（H-07，Gate 条件 b）。
