# ARCH-01 失败 Case Matrix 与验收矩阵

> 中文主档 · 2026-08-29 立档 · 2026-09-24 对齐 #413 最终设计  
> 业务规则来源：[ARCH-01](../../../cards/done/ARCH-01-backup-core-flow-queue-design.md) · [#413](https://github.com/hawkeye-xb/P-Pass/issues/413) · [最终设计摘要](final-design-413.md) · [设计归档](README.zh-CN.md)

本文件是生产实现前的测试合同。每一项先写成会失败的自动行为测试，确认失败原因正确后才写最小实现。它不引入新产品语义，也不决定表结构或 UI。

每行的读法：**Given + When = 触发条件**；**Then = 期望**；**反证 = 去掉哪条保护，这条测试就必须变红**；**真机验收 = 验收人的操作步骤与可见结果**。各行依据见 [`final-design-413.md`](final-design-413.md)。ID 保持稳定：语义仍在的行沿用原 ID，作废的行标「已废弃」并写明原因，新规则追加新 ID。

## 三层证据

| 层 | 目的 | 谁执行 |
|---|---|---|
| 合同测试 | 用公开命令和账本投影锁定业务规则 | 开发自动执行 |
| 故障/反证测试 | 模拟崩溃、迟到回执和并发；移除保护时必须变红 | 开发自动执行 |
| 真机验收 | 验证 UI、系统唤醒、真实连接与用户可见结果 | 验收人 |

真机验收只使用独立测试相册；不对真实照片库做写入、删除或破坏性操作。

## 执行顺序

```text
O order 与三层模型
→ D 发现与计数
→ R 读文件
→ C 传输循环、中断与失败
→ H 桌面健康与半截
→ E 完成凭据
→ X 暂停、取消、恢复与改范围
→ P 换 Desktop
→ 调度、UI
```

## P0：order 与三层模型

| ID | Given | When | Then | 反证 | 真机验收 |
|---|---|---|---|---|---|
| O-01 | 范围内新拍一张 #N，其 generation 大于 G；#N 没有 order | 触发，循环启动 | `GENERATION_MODIFIED > G LIMIT 1` 取到 #N；准备时引用导入算 hash、建 order → offer → 拉取 → 已确认；状态与 G 的推进同一次写入 | 去掉按 G 取新照片时，#N 在这次循环里不被传，必须失败 | 测试相册里拍一张，保持 App 在前台，它在不打开设置、不等兜底的情况下变为已备份 |
| O-02 | 已废弃：慢路径兜底快路径漏掉的照片 | — | 不再有慢路径；generation 不大于 G 的未备份照片从哪条取件来源进入，列为待确认 | — | — |
| O-03 | #K 已确认，hash=H；MediaStore 重建后 #K 的 `_id` 变成新值，内容不变 | 新 `_id` 进入待办并被取件 | 准备时引用导入算出 H（读 1 次），offer 时桌面按 hash 回「已有」→ 新行已确认；传输字节数为 0 | 去掉桌面判重、一律拉取时，传输字节数大于 0，必须失败 | 自动测试为主；真机只核对大规模媒体库变化后首页已备份数不回落 |
| O-04 | #K 已确认，hash=H1 | 用户编辑 #K 并保存，内容变为 H2 | 按新版本传：新建一行，传输至已确认；H1 那一行仍为已确认 | 只按 `_id` 判重（不看版本 / hash）时 H2 不传，必须失败；编辑后改写 H1 那一行的状态时也必须失败 | 在测试相册编辑一张已备份照片（如旋转或裁剪），它再次被传到桌面 |
| O-05 | #S 在待办里，原文件已从手机删除 | 取件后进入准备 | 准备时发现原文件不在，当场记「源已删」；不再尝试传输，也不重试 | 让源已删的 order 保持可重试时，每次兜底都会重试并失败，必须失败 | 测试相册里一张待传照片先在系统相册删除，再打开 App；该照片不再出现在待传进度里 |
| O-06 | 已暂停，待办 N 张 | 用户确认「取消剩余 N 张」，随后兜底对账运行 | 同一事务：N 张写进跳过名单、在途 order 改用户跳过；对账对这 N 张既不补传也不重试 | 取消只退出循环、不写跳过名单时，下一次触发把 N 张全部补传，必须失败；让对账把跳过名单里的照片放进补传时也必须失败 | 测试相册放 5 张新照片，传出第 1 张后暂停并点「取消剩余 4 张」，杀 App 重开并等后台唤醒，这 4 张始终不传 |
| O-07 | 新照片 #R 的最后一块已到达，桌面发出完成凭据 | 手机提交；故障注入：写入过程中崩溃 | 已确认与 G 的推进在同一次写入中生效；崩溃后要么两者都在，要么都不在（此时重启再传一次，桌面按 hash 回「已有」） | 把状态与 G 拆成两次写入时，能观察到「已确认但 G 未推进」或「G 已推进但未确认」，必须失败 | 自动测试为主 |
| O-08 | #K 已确认，桌面上该文件被外部删除，手机原图仍在 | 兜底对账分页询问桌面 | 新建一行 order（id 与原行不同），排在取件第 ④ 级，传输至已确认；原行不改 | 发现缺失后只记录不补传，或复用原 order id（桌面对已完成的同编号直接回完成、实际不补）时，必须失败 | 在专用测试副本上从桌面删除一张已备份照片，打开 App；它被自动重新传回 |
| O-09 | #F 为失败 | 兜底对账运行两次，#F 每次重试都失败 | 每次对账只重试一次（新建一行）；不在同一次对账里循环重试；累计次数有上限 | 去掉「每次一次」的限制时出现无穷重试，必须失败；去掉对账重试时 #F 永远不再尝试，也必须失败 | 自动测试为主 |
| O-10 | 任意时刻 | 对范围内每张照片查询状态 | 每张要么已确认，要么在跳过名单里，要么在待办里；待办张数 = 范围内 − 跳过名单 − 已确认，精确 | 把待办物化成一张会过期的列表时，改范围或恢复后计数与实际不符，必须失败 | 自动测试为主 |
| O-11 | #K 已确认，桌面缺失，手机原图也已删除 | 兜底对账 | 原行保持已确认；没有原图可补，补传的新行在准备时记「源已删」，不重试 | 把原行改成失败或其他状态时，「已确认不可否定」被破坏，必须失败 | 自动测试为主 |
| O-12 | 有一条遗留的传输中 order #L，G=100；#L 的 generation 为 50 | #L 续传完成并提交 | 只写状态，不推进 G；G 仍为 100 | 已有 order 提交也推进 G 时，G 被改写，必须失败 | 自动测试为主 |
| O-13 | #E 传输中被中断；中断期间用户编辑了 #E | 继续后续传 #E | 导入 hash 与 order 上的 hash 对不上 → 这一行改「源已删」并发 `cancel_tuple`；新版本作为新照片另行传输；旧版本已确认的行（如有）保留 | 按旧 hash 续传完成时，桌面拿到的是旧版本，必须失败 | 传一张大照片途中暂停，编辑它再继续：桌面收到编辑后的版本 |
| O-14 | 待办含相册 A 的照片 | 用户把相册 A 移出范围 | 不写任何 order 状态；待办张数立即不再包含 A 的照片 | 改范围时批量改写 order 状态时，必须失败 | 取消勾选一个测试相册，首页待备份张数立即减少 |

| ID | Given | When | Then | 反证 | 真机验收 |
|---|---|---|---|---|---|

| D-02 | 循环正在传 #1 | 连续到达 3 次触发 | 只有一个循环在跑；触发合并，不启动第二个循环，不重复申请 FGS | 每次触发各起一个循环时，出现并发传输或多次 FGS 申请，必须失败 | 传输中连拍 3 张测试照片，通知栏只有一条 FGS 通知 |

| D-04 | G 丢失或被清零；多数照片已确认 | 取新照片 | 不丢照片；已确认的照片不重新传输字节（桌面按 hash 回「已有」） | 桌面判重失效时会重传已确认照片，必须失败 | 自动测试为主 |
| D-05 | 已废弃：`getVersion` 变化触发全量对账 | — | 不再有本地全量对账 | — | — |
| D-06 | 已废弃：慢路径只对变化的照片算 hash | — | 不再有本地对账；读文件次数见 R 组 | — | — |
| D-07 | 有多个外部卷 | 取新照片 | G 按卷分开存、按卷查询；API 26–29（无 `GENERATION_MODIFIED`）的取件来源待确认 | 只查一个卷时，其它卷上的照片不传，必须失败 | 插 SD 卡的机器上，SD 卡测试相册里拍一张，它被正常备份 |
| D-08 | 范围内 10 张，其中 3 张已确认、2 张在跳过名单；范围外另有 5 张 | 入口计数 | 计数 = 5，精确；只读元数据，不读文件，不申请 FGS | 计数不加范围条件时得到 10，必须失败；计数时读文件或申请 FGS 时也必须失败 | 首页待备份张数与测试相册里未备份张数一致 |

## P0：读文件

| ID | Given | When | Then | 反证 | 真机验收 |
|---|---|---|---|---|---|
| R-01 | 新照片 #N，桌面没有这份内容 | 准备 + 传输 | 原图共读 2 次：引用导入（hash + outboard）1 次、供数 1 次；不写副本；Kotlin 侧不再单独算 hash | 保留 Kotlin 侧单独算 hash 时读 3 次，必须失败 | 自动测试为主（计数读打开次数） |
| R-02 | 新照片 #N，桌面已有这份内容 | 准备 + 传输 | 原图读 1 次（引用导入），桌面回「已有」即完成 | 桌面已有仍供数时读 2 次，必须失败 | 自动测试为主 |
| R-03 | 已有 order（遗留续传 / 用户恢复 / 对账补传），桌面已有 | 准备 + 传输 | 原图读 0 次，hash 从 order 读 | 已有 order 重新导入算 hash 时读 1 次，必须失败 | 自动测试为主 |
| R-04 | 引用导入条件不满足：API 29（`dataPath` 为空）、路径与 fd 不一致、文件 ≤ 16 KiB、或 `has()` 为 true | 导入 | 回退复制，读缓冲 1 MiB；结果 hash 与引用导入一致；算 hash、供数都流式，内存恒定 | 条件不满足仍走引用时读到错误字节，必须失败 | 真机验证引用导入路径可读、字节一致 |
| R-05 | 供数途中原文件被改、截断或删除 | 供数 | 供数中止，通过现有状态回报；不把残缺内容确认为完成 | 继续供出变化后的字节时，桌面校验失败或确认了错误内容，必须失败 | 自动测试为主 |

## P0：传输循环、中断与失败

| ID | Given | When | Then | 反证 | 真机验收 |
|---|---|---|---|---|---|
| C-01 | 备份中，#18 正在传输 | 用户暂停 | 写暂停标志 → `flow.suspend`（同步、不可取消、约 3 秒内返回）→ 退出循环 → 释放 FGS 与 wakelock；#18 保持传输中，桌面半截保留；全局 = 已暂停 | 暂停后仍持有 FGS、下一张开始，或发 `flow.cancel` 丢掉半截时，必须失败 | 传输中点暂停：3 秒内 FGS 通知消失，没有下一张开始 |
| C-02 | 已暂停 | App 重启、后台唤醒、网络恢复、重复触发 | 仍已暂停；入口第一步查到暂停即结束：不计数、不申请 FGS、不传输 | 任一触发跳过暂停检查、或能清除暂停时，必须失败 | 暂停后杀 App 重开、切前后台、开关 Wi‑Fi，仍显示暂停，通知栏无 FGS 通知 |
| C-03 | 已暂停，#18 传输中未完成，另有新照片与对账补传 | 用户继续 | 清除暂停标志 → 回到入口；取件顺序 #18 → 新照片 → 对账补传 | 继续后先取新照片时，#18 不是第一张，必须失败 | 暂停一张传到一半的照片后继续，进度从这张继续 |
| C-04 | 未暂停；仅 Wi‑Fi 开启但当前是移动网络（或电量低、额度耗尽、未配对） | 任一触发 | 入口条件不通过：不申请 FGS；全局 = 等待中（对应原因），原因持久化；登记对应的唤醒 | 条件不满足仍申请 FGS，或不登记唤醒导致条件恢复后不自动继续，必须失败 | 开「仅 Wi‑Fi」后切到移动网络：无 FGS 通知；切回 Wi‑Fi 后自动开始传 |
| C-05 | #18 正在传输 | Wi‑Fi、电量条件丢失，或 FGS 被系统收回、断网 | `flow.suspend`，退出循环、释放 FGS；#18 保持传输中，不计入失败；全局 = 等待中；唤醒后自动续传 #18 | 把等待计为失败，或恢复需要用户继续，必须失败 | 传输中关掉桌面，再打开：自动续传，不出现错误或「继续」按钮 |
| C-06 | 有 3 张待传，条件都满足 | 一次触发 | 整个循环只申请一次 FGS + wakelock + 一条推送订阅；3 张传完、取不到下一张后释放三者 | 按单张启停 FGS、或每张各开一条订阅时，必须失败 | 连续传 3 张，通知栏 FGS 通知不闪烁，传完后消失 |
| C-07 | 循环中，#18 已完成 | 取 #19 前条件已变（例如刚进入暂停或 FGS 已失效） | 每张开始前重检暂停 / 条件 / FGS / 配对；不满足则不开始 #19 并退出 | 只在循环开头检查一次时，#19 在条件不满足下开始，必须失败 | 自动测试为主 |
| C-08 | 后台触发，申请 FGS 被系统拒绝 | 之后再有后台触发 | 全局 = 等待中（`FGS_BLOCKED`）；下次触发照常重试申请，不持久卡死到回前台 | 被拒后记成持久受阻、直到回前台才重试时，必须失败 | 自动测试为主；Android 15 开机后台启动 dataSync FGS 另做真机实验 |
| C-09 | #18 读取失败（单张失败） | 传输 #18 | 当场重试 1 次；仍失败记「失败」，循环继续 #19 | 不重试、无穷重试，或失败卡住后续照片，必须失败 | 自动测试为主 |
| C-10 | #18 连接还在，但连着 3 分钟没有新的文件字节（`Progress.end_offset` 不前进） | 传输判定 | 主动断开，判为路径失败：#18 保持传输中，退出循环、释放 FGS，不计入单张失败 | 无限等待，或把路径失败记为失败，必须失败 | 自动测试为主 |
| C-11 | 15 秒没有桌面来连 | 传输判定 | 先问桌面状态；回答 active 就继续等，不判失败 | 15 秒直接判失败时，必须失败 | 自动测试为主 |
| C-12 | 桌面回报 `storage_full` / `library_unavailable` / `storage_failed`（对端失败） | 传输 #18 | 映射为对应的对端失败原因并带回手机显示；退出循环、释放 FGS；#18 不计入单张失败次数；全局 = 等待中（`DESKTOP_STORAGE_FULL` / `DESKTOP_LIBRARY_UNAVAILABLE` / `DESKTOP_STORAGE_ERROR`）。`fetch_failed` 按路径失败，未知 code 按单张失败 | 把对端失败计入单张次数，或不读 code 一律当单张失败时，必须失败 | 桌面磁盘写满后传一张：手机显示桌面空间不足、不出现失败计数；清出空间后下一次唤醒自动传完 |
| C-13 | #18 正在传输 | 网络回调 `onLost` | 立即判路径失败，不等 3 分钟超时 | 只靠 3 分钟无字节判定时，`onLost` 后仍空等，必须失败 | 传输中关掉手机 Wi‑Fi：FGS 通知立即消失 |
| C-14 | 路径失败，桌面不可达 | 之后 30 分钟内没有网络变化 | 挂网络变化回调 + 3 次间隔 10 分钟的探测，每次探测就是一次触发；不计次 | 不登记探测、或把路径失败计入单张次数时，必须失败 | 自动测试为主 |
| C-15 | 全局为空闲或等待中 | 用户点暂停 | 不生效：暂停只在备份中可用 | 在等待中写入暂停标志时，必须失败 | 自动测试为主 |
| C-16 | 全局为等待中（某原因） | 进程被杀后重启 | 等待原因仍在，界面显示同一原因 | 等待原因只在内存里时，重启后丢失，必须失败 | 开「仅 Wi‑Fi」切到移动网络，杀 App 重开，仍显示等待 Wi‑Fi |

## P0：桌面健康与半截

| ID | Given | When | Then | 反证 | 真机验收 |
|---|---|---|---|---|---|
| H-01 | 桌面探测回复 `health` 显示照片库不可写（或索引库异常、空间耗尽） | 入口探测 | 不申请 FGS；全局 = 等待中（具体原因）；桌面发系统通知 | 不看健康状况照常申请 FGS 并开始传输时，必须失败 | 把桌面照片库文件夹设为只读：手机显示对应原因、无 FGS 通知，桌面弹出系统通知 |

## 必须可观察的证据

测试与真机诊断只记录状态事实，不写照片名称、路径或内容：

```text
发现：G 前后、取件来源（遗留续传 / 用户恢复 / 新照片 / 对账补传）、入口计数
读文件：每张照片的打开次数、引用导入或回退复制

传输：FGS、wakelock、推送订阅的申请 / 释放；每张开始前的重检结果；flow.suspend / cancel_tuple 调用
状态：全局状态转换；暂停标志；等待原因（持久化）与恢复原因
失败：中断 / 路径 / 单张 / 对端分类，对端失败 code，单张重试次数
桌面：探测带回的 health、offer 预检结果、半截回收
配对：旧运行数据清理完成；用户配置保留
```
