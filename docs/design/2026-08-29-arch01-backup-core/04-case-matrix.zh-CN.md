# ARCH-01 失败 Case Matrix 与验收矩阵

> 中文主档 · 2026-08-29  
> 业务规则来源：[ARCH-01](../../../cards/ARCH-01-backup-core-flow-queue-design.md) · [设计归档](README.zh-CN.md)

本文件是生产实现前的测试合同。每一项先写成会失败的自动行为测试，确认失败原因正确后才写最小实现。它不引入新产品语义，也不决定 DB、文件或 UI。

## 三层证据

| 层 | 目的 | 谁执行 |
|---|---|---|
| 合同测试 | 用公开命令和账本投影锁定业务规则 | 开发自动执行 |
| 故障/反证测试 | 模拟崩溃、迟到回执和并发；移除保护时必须变红 | 开发自动执行 |
| 真机验收 | 验证 UI、系统唤醒、真实连接与用户可见结果 | 验收人 |

真机验收只使用独立测试相册；不对真实照片库做写入、删除或破坏性操作。

## 执行顺序

```text
D 发现原子性
→ C 消费控制
→ E 完成凭据与范围
→ X 取消本轮
→ P 换 Desktop
→ R Restore / Discard 与远端对账
→ 原生传输 adapter、调度、UI
```

| ID | Given | When | Then | 反证 | 真机验收 |
|---|---|---|---|---|---|
| D-01 | 水位 W 后有 500 个候选 | 提交一页发现 | 500 项入待传列表，水位前移到该页末尾 | 只写水位、不写队列时必须失败 | 无需手工制造 |
| D-02 | 同 D-01 | 在本地提交前模拟崩溃 | 队列与水位都不变化；重启后仍发现这 500 项 | 先前移水位时必须失败 | 发现过程中杀 App 后重开，待传项不丢 |
| D-03 | D-01 已提交后立即崩溃 | 重启后再次触发发现 | 不重复创建同一媒体版本的待传项 | 去掉稳定身份去重时必须失败 | 同一测试相册反复前后台切换，不产生重复待传数 |

## P0：消费控制与严格队头

| ID | Given | When | Then | 反证 | 真机验收 |
|---|---|---|---|---|---|
| C-01 | #18 正在原生传输，#19 在后 | 用户 Pause | #18 停止；partial 保留；UploadCursor 停在 #18；#19 不开始 | 让 #19 开始时必须失败 | 传输中 Pause，观察没有下一张开始 |
| C-02 | 已 Pause | App 重启、后台唤醒、网络恢复、重复触发 | 仍 Pause；不传输 | 任一唤醒能清 Pause 时必须失败 | Pause 后杀 App 重开、切前后台、恢复网络，仍须显示 Pause |
| C-03 | 已 Pause，#18 未完成 | 用户 Continue | 只从 #18 继续；不创建 Manual/全量新管道 | Continue 改为新任务时必须失败 | Continue 后从原待传项继续 |
| C-04 | #18 正在传输 | Wi‑Fi/电量/Desktop 条件丢失 | 停止且保留 partial；不增失败次数；条件恢复自动续 #18 | 把等待计为失败或要求 Continue 时必须失败 | 关 Wi‑Fi 或 Desktop；恢复后自动继续，不出现错误/Continue |
| C-05 | #18 有真实永久错误 | 重试预算耗尽 | #18=`FAILED_NEEDS_USER`；严格队头才可前进到 #19 | 永久错误仍无穷重试或跳过未记录时必须失败 | 自动测试为主；真机只核验错误文案与后续可操作入口 |

## P0：完成凭据与范围竞争

| ID | Given | When | Then | 反证 | 真机验收 |
|---|---|---|---|---|---|
| E-01 | #18 Desktop 已完整接收、验证、可靠保存并给出完成凭据 | 手机处理凭据 | #18=`CONFIRMED`；UploadCursor 前进 | 仅“开始传输”即确认时必须失败 | 一张照片完成后显示已备份 |
| E-02 | #18 已有完成凭据 | 用户减少范围，回执晚到 | #18 仍 `CONFIRMED` | 范围变化覆盖完成事实时必须失败 | 先完成测试照片再移出相册，完成记录保留 |
| E-03 | #18 无完成凭据/仅 partial | 用户减少范围 | #18=`CANCELLED_BY_SCOPE`；partial 不得最终确认 | 旧 partial 最终确认时必须失败 | 未完成照片传输中移出相册，不得继续完成 |
| E-04 | #18 已确认 | 用户 Cancel Current Round | #18 保留 `CONFIRMED` | 已完成项变取消时必须失败 | 已完成照片不受取消影响 |

## P0：取消本轮

| ID | Given | When | Then | 反证 | 真机验收 |
|---|---|---|---|---|---|
| X-01 | 用户已 Pause；本轮已发现 500 项、待发现 400 项 | Cancel Current Round | 先取消 500；继续分页发现并取消 400；零项进入传输 | 只取消眼前 500 时必须失败 | 小测试相册可做简版；900 项由自动测试覆盖 |
| X-02 | 取消轮活动 | 新项进入待传列表 | 新项直接 `CANCELLED_BY_USER_ROUND` | 新项变 `QUEUED` 时必须失败 | Cancel 中新增测试照片/触发发现，确认不传输 |
| X-03 | 取消轮分页到一半 | App 重启 | 从保存的取消进度继续；不漏取消、不重复传输 | 重启后重置或遗漏时必须失败 | 自动测试为主 |
| X-04 | 本轮待传列表清空 | 原子结束 CancellationRound 后有新项入队 | 新项属于下一轮，可正常 `QUEUED` | 结束后仍取消新项时必须失败 | 取消结束后拍一张测试照片，应进入后续备份 |
| X-05 | 某轮已取消 | 用户 Restore / Discard | Restore 仅重新准入该轮未完成项；Discard 仅关闭快捷恢复 | 普通触发自动复活取消项时必须失败 | 验收 Restore/Discard 入口与结果 |

## P0：换 Desktop 与旧结果隔离

| ID | Given | When | Then | 反证 | 真机验收 |
|---|---|---|---|---|---|
| P-01 | 有 Wi‑Fi/电量/相册配置，且有队列、水位、取消轮、partial | 改配对 Desktop | 配置保留；旧队列、水位、取消轮、partial、运行归属清理 | 清配置或保留旧运行数据时必须失败 | 换 Desktop 后检查配置仍在、旧待传不带入 |
| P-02 | 已换到新 Desktop | 旧 Desktop 回执抵达 | 旧回执无权改变新传输历史 | 旧回执确认新历史项时必须失败 | 自动测试为主 |

## P1：远端对账

| ID | Given | When | Then | 反证 | 真机验收 |
|---|---|---|---|---|---|
| R-01 | 已确认项在 Desktop 外部缺失，手机原图仍在 | 低频对账 | `remotePresence=MISSING` + `NEEDS_DECISION`；不自动补传 | 缺失即自动传时必须失败 | 在专用测试副本上验证提示，不碰真实原图 |

## 必须可观察的证据

测试与真机诊断只记录状态事实，不写照片名称、路径或内容：

```text
发现页：页大小、水位前后、入队数、取消数
控制：Pause / Continue 已持久化；等待原因与恢复原因
单张：队列序号、状态转换、失败原因、完成凭据已接收
取消轮：开始、每页进度、结束、取消总数
配对：旧运行数据清理完成；用户配置保留
```

## 验收人 review 清单

在每张实施卡开始前，验收人只需确认：

- [ ] 该卡覆盖了本矩阵的具体 ID；没有私自扩展产品语义。
- [ ] 每个自动 case 都有 Given / When / Then 与可重复命令。
- [ ] 每个 P0 风险都有反证：移除关键保护后测试会变红。
- [ ] 真机步骤只用测试相册，且说明预期的用户可见结果。
- [ ] 日志证据没有照片路径、名称或内容。

在每张实施卡完成后，验收人只需查看：红→绿输出、反证输出、对应真机 checklist；不必手动制造崩溃、900 项分页或竞态。
