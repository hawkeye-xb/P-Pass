# 任务卡模板

> 复制本文件开新卡，文件名 `<领域>-<编号>-<kebab-简述>.md`。
> 头部五段是**必填**（缺字段=不受理，见 `docs/AGENT_PROTOCOL.md` §C.2）。
> 写给任何人看：只读头部就该看懂"什么问题、修好什么样、怎么算完"。

```markdown
# <卡号> <一句话标题>

> ✅/🟡/⬜ 状态：<未开工 | 代码已合并（commit xxx）等真机验收 | 已归档>
> 级别：L0-L3 · 阻塞：<无 | 等谁什么决定>

## 问题
<现象 + 复现步骤。写用户/系统真实观察到的行为，不假设读者看过别的卡。>

## 期望行为
<修好后应该什么样。>

## 验收标准
- [ ] <可逐条打勾的判据：跑什么命令/做什么动作 → 看到什么>
- [ ] （L1+ 故障类必带反证：去掉故障条件的变体必须变红）

## 范围
- 只准动：<文件/目录>
- 不准动：<相邻但不属本卡的东西>

## 阻塞与依赖
<等拍板的决定 / 前置卡 / 需要的环境。无就写"无"。>

---
<!-- 以下自由段落：根因分析、方案对比、实施记录、验收证据。
     实施 agent 追加，不删历史。 -->

## 实施记录
<commit、测试输出摘录、真机证据>

## 备注
<已知边界、教训、相关平台事实>
```

## 硬规矩

1. **状态横幅三档**（规则来源：本目录 README.md）：
   - `✅ 代码已合并（commit xxx），<日期> 归档` → 移入 `done/`
   - `🟡 代码已合并，等真机验收` → 留在本目录，写清"已做什么/还差什么"
   - `⬜ 未开工`（或无横幅）= 一行代码都没写
2. **卡里不写本机状态**：本机路径、设备序列号、开发机用户名、本地副本
   目录名一律不进卡。这类信息属于 `local-state.md`（不进 git）。
   测试环境只写与平台行为有关的通用事实（如"三星 One UI 测试机"）。
3. **跨卡声明禁令**：不许写"兄弟卡 Y 已修复"。Y 未合并只能写
   "待 Y 合并后成真"，或列为本卡前置（§C.2）。
4. **报绿纪律**：附命令 + 输出摘要；只跑一半不算全绿。
