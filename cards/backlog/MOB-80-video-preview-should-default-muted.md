# MOB-80 视频预览应默认静音（backlog · 待换播放器时一并做）

**状态**：⬜ 未开工 · backlog（用户 2026-09-15 提出，当场决定「先记录，下次换
播放器时一并做」——不单独立刻实施）

## 问题

移动端大图/视频查看器（`ui/VideoScreen.kt`）用 Media3 `ExoPlayer` +
`PlayerView`，`playWhenReady = true` 自动播放但没设静音，点开一个视频就
立刻有声音。桌面端 `App.svelte` 用原生 `<video>`，没有自动播放属性，本来
就不会自己出声，不受影响——**本卡范围只在移动端**。

## 为什么不是「调音量条到最小」这么简单

当场核查过 Media3 `PlayerView` 自带的默认控制条：只有播放/暂停/进度条，
**没有音量滑块，也没有静音按钮**。「默认静音」要做成能用的功能，必须先在
UI 上加一个音量控制入口（否则用户点开视频后永远听不到声音、也没有地方
打开），而不是改一个初始值就完事。

## 已讨论过的两条路（等换播放器时按实际选型重新评估）

1. 加一个喇叭图标，单点切换静音/有声（类似抖音/Ins 信流视频），工作量小，
   但只有开/关两档，不能连续调节。
2. 加一根真正的音量滑块，可从 0 拖到最大，需要自定义控制层叠在
   `PlayerView` 上（Media3 默认控件不提供滑块），工作量明显更大。

用户当场选择：不在现有播放器上加这层 UI，等下次评估/更换视频播放器组件时
把「默认静音 + 音量控制入口」作为需求点一并设计，避免在将被替换的组件上
先做一次可能被推翻的定制。

## 期望行为（留给下一次播放器选型时细化）

- 打开视频查看器时默认静音（`volume = 0f` 或等价设置）。
- 提供用户可发现、可操作的音量/静音控制（具体形式看播放器选型，见上方
  两条路）。
- 桌面端 `<video>` 不受影响，不需要改动。
