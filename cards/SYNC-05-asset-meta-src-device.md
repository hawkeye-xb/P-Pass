# SYNC-05 AssetMeta 补 src_device，消灭客户端影子状态

> ⬜ 状态：未开工
> 级别：L1 · 阻塞：无（独立，无依赖，随时可先做）

## 问题

Android 的"仅本机/家人的"筛选器目前靠客户端自己攒的本地影子状态（读本地
`backup-state` 目录重建 hash 集合）判断资产来源；而服务端 `asset` 表本来
就有 `src_device` 这一列，只是线上 `AssetMeta` 没发出来。客户端该读的字段
没在线上协议里，导致维护一份多余的、可能漂移的本地状态。

背景与全部裁决点见 `docs/product/2026-08-12-metadata-sync-decisions.md`
（§⑧，本卡实现这一条）。

## 期望行为

线上 `AssetMeta` 补 `src_device` 字段；Android 筛选器改读这个字段，删掉
客户端自己攒的那份本地影子状态（不保留静默 fallback——那样等于影子状态
没有被真正消灭，只是加了一条新路径在旁边，跟本卡目标相反）。

## 验收标准

- [ ] proto 单测：`AssetMeta` 序列化/反序列化包含 `src_device`，且缺省时（旧数据/旧协议）有明确的空值行为，不 panic
- [ ] Android 单测：筛选器逻辑改用 `src_device` 判断后，给定一组 `AssetMeta`（包含本机/家人/空值三类）→ 断言各筛选器分类结果跟「备注」里的安全默认一致（空值只在"全部"露出，不进"仅本机"/"仅家人"）
- [ ] 反证：删掉本地 `backup-state` 目录（模拟这份本地状态从未存在过）→ 筛选器依然能正确分类本机/家人（证明筛选器真的不再依赖这份本地影子状态，不是"两份数据凑巧一致导致测试碰巧通过"）
- [ ] 证据：单测输出摘要 + 反证的实际输出
- [ ] 收尾：Rust 全量测试绿 + android 全量单测绿 + PROGRESS.md 一行 + 本卡移入 `done/`

## 范围

只准动：
- `crates/proto/src/msgs.rs`（`AssetMeta` 加字段，走 wire 兼容——新字段
  旧客户端忽略即可，不是破坏性变更）
- `crates/daemon/src/query.rs`（`asset_meta` 映射函数补上这个字段）
- `apps/android/app/src/main/java/com/hawkeyexb/ppass/ui/PhotosScreen.kt`
  （筛选器逻辑：`mine`/`Local`/`Family` 判断改读 `src_device`，删掉
  现在读本地 `backup-state` 目录重建 hash 集合那段逻辑）

不准动：
- SYNC-02/03/04 涉及的任何文件（协议加字段是纯扩展，跟订阅机制无关）

## 备注

### 设计要点

- **空 `src_device` 的处理（2026-08-13 更新：不再阻塞本卡）**：只有
  `rebuild()`（从磁盘硬重建索引，见 `docs/runbook/lost-or-corrupted-index.md`）
  才会产生空 `src_device`——而 `rebuild()` 现在在产品里没有任何调用
  点，正常运行时（手机备份 / WATCH-01 本地监听）都会正确赋值，不会
  真的撞到这种资产。**用户已裁决：这个空值分类的最终展示规则不用现在
  拍板，先挑一个安全默认（比如空值时只在"全部"筛选器下露出，不归入
  "仅本机"/"仅家人"任一档，不擅自归因），真正决策延后到"重建索引"
  功能本身被排期实现的时候一起定**——本卡实施 agent 不用为这条卡住，
  按上述安全默认写代码即可，测试断言跟着这个默认走。
- 手机自己的 `NodeId` 判定"是不是本机"，不需要额外协议往返，客户端
  本来就知道自己的身份。

### 跨卡声明禁令

不许写"筛选器逻辑已简化"却仍然保留本地 `backup-state` 读取路径作为
静默 fallback。
