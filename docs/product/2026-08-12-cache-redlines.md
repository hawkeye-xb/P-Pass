# 手机端缓存红线备忘（MOB-04，2026-08-12）

> 用户方向（2026-08-12）：手机是**减负端**，不是第二存储端。
> 未来任何「手机端缓存/查看」类卡必须引用本备忘，红线写进代码注释。

## 现状事实（写卡前已核对）

- 缩略图缓存 = **内存 LruCache，上限 32MB 估算（≈838 张 256px 解码位图），
  退出进程即清，不落盘**（`PhotosScreen.kt` `thumbCache`）。
- 用户看到旧图的根因在 **daemon 侧**（Finder 删了 originals，索引/thumb
  没清）——SYNC-01 修复；手机端缓存本身没有囤图问题。

## 三条红线（代码注释 + 守卫测试 CacheRedlineTest）

1. **失效联动**：timeline 整页重载后，已不在返回集里的 hash 必须从内存
   缓存逐出（`TimelineLoader.onTimelineRefreshed` + `staleThumbKeys` 纯
   函数）；翻页追加只增不逐。不做 → SYNC-01 对账后 daemon 已删、手机
   内存还闪旧图直到进程死。
2. **缩略图不落盘**：现状保持。任何改动不得引入磁盘 thumb 缓存
   （CacheRedlineTest 扫描全工程源码 grep 守卫）。
3. **大图红线（预埋给未来查看功能）**：拉原图只走**临时文件即看即清**
   或**纯内存流式**，**绝不建长期原图缓存**——手机是减负端不是第二存储端。
