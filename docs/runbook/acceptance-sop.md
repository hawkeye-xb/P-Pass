# 验收 SOP 模板（owner 写给产品负责人照做）

验收模型见 AGENTS.md「按版本验收」：owner 按验收台账里的待验 / 待重验项给 SOP，产品负责人照做，owner 读日志和截图判定，
没有意外就算通过，判定后由 owner 在台账里勾掉对应项。下面是一份 SOP 的骨架，复制后按改动填。

写之前：

- 先 grep 界面的显示条件，不凭印象写入口；按钮名、词名对着实物写（AGENTS.md「验收」）。
- 每一步都写「日志里出现哪一行算通过」，成功路径也要有日志行；判定脚本只把真正必需的步骤设成失败项。
- 只验未知：能从已有实测推出来的不让人重做。

---

## <PR 或模块卡>：<一句话说要验什么>

**设备**：<mac（本机 P-Pass 桌面 App）/ ios / android，哪台、什么版本>

**开始前（owner 做，人不用管）**：替你拿住涉及的设备，期间别的会话的自动场景排队等，不会动这些设备：

```bash
tools/e3/lock hold-for-human <设备...>
```

`tools/e3/lock status` 显示「人工验收中」后再把 SOP 发出去。

**步骤**：

| # | 你做什么 | 看到什么算对 | owner 判定看的日志行 |
|---|---|---|---|
| 1 | <操作> | <界面上的现象> | `<日志里的一行>` |
| 2 | … | … | … |

**做完告诉 owner**：每步截图或录屏（有就发，没有也行），以及有没有意外。

**结束（owner 做）**：读日志与截图判定，然后

```bash
tools/e3/lock release-human <设备...>
```

通过后在验收台账（「[验收] <正式 tag>」issue，如「[验收] v2026.11.2」）里把对应项的 `[ ]` 勾成 `[x]`，行尾可补：

```
| 结论：产品负责人 <日期 时间> 按 SOP <这份 SOP 的链接> 操作，owner 判日志通过
```

不能代替人去操作，不能编造日志结论；有意外就不勾，把意外记到卡上。

某项确实不用验（例如只改了不影响行为的文案标点）：勾上并在行尾写 `| 结论：免验，理由…`。
免验只对台账里那一项写着的 `@<包>（<提交>）` 成立：它之后相关文件又改过，发版闸仍判待重验，
要先出含这些改动的 test 包、`just release-scope --ledger <台账号> --pkg <test 包 tag>` 更新台账，再验或再写免验。
正式版发版时 Release 自动按标题找这张台账判定（#1486），没清零发不出来。
