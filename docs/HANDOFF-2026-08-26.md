## 这一天最贵的五条教训

### 1. 守卫测试要钉「不变量」，别钉「字面形状」——今天误伤四次

四次都是同一个形状，然后正当的重构改了那串字面量，测试就红，而它**并没有多守住
任何东西**：

```
contains("if (backupInterrupted) return@LaunchedEffect")       ← MOB-35 那条
contains("enqueueReuploads(store.load(), reuploads, lost)")    ← MOB-34 那条
contains("return Result.success()")                            ← 我自己十分钟前写的
sliceBetween(…, "LaunchedEffect(backupInterrupted) {", …)      ← MOB-38 搬家后成批红
```

⚠️ **`MOB-39` 会搬动大量逻辑，这类源码文本断言会成批变红。届时要改的是切片位置，
不是不变量。** 这条已写进 `ForegroundSyncNotFrozenTest` 的注释里。

### 2. 别用正则去猜作用域

我加过一条「不许用 `!backupInterrupted` 把某调用包住」的正则断言，**当场误报**：
Kotlin 单语句 `if` 没有花括号，`if (cond) a()` 之后紧跟的 `b()` 其实在 `if` 之外，
而正则按「N 字符内出现」判命中。**文本匹配做不到作用域判定。**

### 3. 把「我没想到怎么做」写成「已知边界」，等于给错误结论盖章

`MOB-34` 第一版把「存量条目反查不到」写成已知边界、还配测试钉它，我还据此推荐了
「启动时一次性全量迁移」。验收人一句「这不是一个 json 吗？为什么会丢失？重建的话
hash 算出来不一致吗？」把它推翻了——**没有丢失，只是「hash → 本地 _ID」这一个方向
的索引没存；而那张表（`hash-cache.json`）一直在盘上，跨版本跨配对存活。**

### 4. 「天然一次性，连去重窗口都不用做」这种话要警惕

我把 `MOB-29` 通知的一次性说成优点。**那是把缺陷说成优雅**——一次性 = 没有重试 =
发失败即永久静默。省掉一套机制之前先问「省掉的那套本来在防什么」。→ `MOB-37`。

### 5. 验收人说「还是不 OK」时，先做受控实验分清两件事

「机制没做」vs「这次情形不同」。`MOB-36` 那次是后者（他从 Camera 移到 P-Pass，
**两个都是已选相册**，那张早就备份过了 → 正确行为就是什么都不发生）。**直接改代码
就白改了。**

## 派 subagent 的正确姿势（验收人明确批评过）

**别让 agent 先读一堆文档。** 之前的派活单开头是「先读 CLAUDE.md / AGENT_PROTOCOL.md
/ 卡 / TEMPLATE」——那是纯重复消耗（一个 agent 花 20 分钟重新挖我已知的东西）。

正确做法：**把事实内联进指令**——根因、文件、行号、原代码、现有类型定义、已知的坑、
测试计数基线、红线清单。唯一让它读的是那张卡本身。样例见
`MOB-38`/`UX-13` 的派活单（后者存于本轮 scratchpad）。

规则：**派「成本在做」的活，不派「成本在知道」的活。** 十行的改动 + 完整仪式，
仪式成本比改动大一个数量级——那种自己做。

## 几个反复咬人的工具坑

- **`./gradlew` 找不到 Java 时退出码是 0** → 假绿。必须
  `export JAVA_HOME=/opt/homebrew/opt/openjdk`，且**报绿必须给测试计数**
  （从 `test-results/*.xml` 数 + 核对时间戳）。
- **`git add -A` 会吞掉 `.claude/worktrees/`** → 已加进 `.gitignore`，但注意。
- **pre-commit 钩子拦敏感词**（雇主名等）→ 写实测证据时文件名脱敏。
- **`sliceBetween(…, ")")` 会在参数列表中间截断**（第一个 `)` 常落在
  `Modifier.fillMaxWidth()` 里）→ 用有界窗口或更靠后的锚点。
- **CI 是 tag 驱动的**：`-test.N` tag → 自动 prerelease；正式 tag → 停 draft 等
  人工 Publish。`workflow_dispatch` **不注入版本号**，出的包版本会回落，
  **不能用于自动更新测试**。
