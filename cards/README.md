# 任务卡队列（执行 agent 工作入口）

- 本目录 = 当前待做的任务卡，一卡一文件，格式按 `TEMPLATE.md`
  （规范来源 `docs/AGENT_PROTOCOL.md` §C.2）。
- 领卡即开工，做完把卡移到 `done/` 并在卡尾追加验收记录（证据/测试输出摘录）。
- 优先级看卡内标注；无标注按文件名字典序。
- **本机环境状态（路径/设备/本地副本/daemon 状态）不写在卡里、不写在
  docs/ 里**——统一放 `local-state.md`（已 gitignore，不上远端）。
- 流程纪律（直推 main 的三条底线、tag 纪律）见仓库根 `AGENTS.md`——先读它，
  它是模型无关的唯一规范（`CLAUDE.md` 只是指向它的指针）。
- 现在该接哪张卡，看 [`docs/QUEUE.md`](../../docs/QUEUE.md)——唯一待办队列。

## ⚠️ 卡的位置不是事实，代码才是（2026-08-20 教训）

回答"这个功能做了没 / 还差什么"时，**必须先去代码里核实，不能拿卡在哪个
目录当答案**。

2026-08-20 一次上线阻塞盘点里我连续误报三次：`DESK-06`、`SYNC-04`、
`ICON-02` 三张卡的代码早就合并了，只因为卡还躺在本目录，就被报成"未实施"。
其中 DESK-06 让用户以为一个修过的问题又回来了。

根因是流程漏洞：**卡的收尾条件包含"真机验收"，而真机验收挂在用户那边**，
于是"代码已合、等人验"的卡会永久停在待办目录，看起来跟"没做"一模一样。

### 规矩

1. **每张卡顶部必须有状态横幅**，三档之一：
   - `✅ 状态：代码已合并（commit xxx），<日期> 归档` → 同时移入 `done/`
   - `🟡 状态：代码已合并，等真机验收` → 留在本目录，但必须写清"已做什么 /
     还差什么"
   - （无横幅）= 真的一行代码都没写
2. **核实要对着卡面要求逐条找**，不能一个宽泛 grep 了事。SYNC-04 那次
   误报就是查错了文件（订阅在 `PhotosScreen.kt`，我去 grep 了
   `TimelineLoader.kt`）。
3. 代码合并即刻加横幅，**不要等验收**——横幅和归档是两件事。
