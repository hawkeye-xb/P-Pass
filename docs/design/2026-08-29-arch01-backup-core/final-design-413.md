# 备份核心重构：最终设计（2026-09-24 对齐）

基线：`feat/413-per-item-loop` @ 272fd591。差异证据见 #413 评论。

## 1. 模型：三层
| 层 | 存什么 | 谁写 |
|---|---|---|
| 意图 | 相册范围、跳过名单、暂停标志 | 只有用户操作 |
| 事实 | order：一次传输一行（`_id`、version、hash、状态、失败次数） | 只有执行循环与对账 |
| 待办 | 不存；现算 = 范围内照片 − 跳过名单 − 已确认 | 纯函数 |

- 取件固定优先级：遗留续传 → 用户恢复 → 新照片 → 对账补传（桌面缺失、失败重试）。
- 范围只作查询条件，不写成 order 状态。
- 补传不复用原 order id（桌面对已完成的同编号直接回完成），新建一行。
- 新照片按 G（`generation > G LIMIT 1`）取；G 只服务新照片，只有新照片提交时推进。

## 2. 主流程
入口（不持有 FGS、不读文件）：用户暂停？→ 计数（精确）→ 条件（配对 / 仅 Wi-Fi / 电量 / 额度）→ 探测桌面 + 桌面健康 → 申请 FGS + wakelock + 一条推送订阅。
循环每张：重检 → 取件 → 准备（拿 hash：已有 order 读表；新照片引用导入算出）→ 传输（offer，桌面按 hash 判重，“已有”即完成；否则拉取）→ 提交。
取不到 → 释放 FGS、订阅、wakelock。

## 3. 读文件
- 新照片需传输：2 次（引用导入算 hash + outboard；供数），不写副本；删掉 Kotlin 侧单独 hash。
- 新照片桌面已有：1 次。已有 order 桌面已有：0 次。
- 算 hash、供数都流式，内存恒定。
- 引用导入不满足条件（API 29、路径与 fd 不一致、≤16 KiB、`has()` 为 true）回退复制；回退读缓冲 1 MiB。
- 去掉本地对账：是否已有以桌面判重为准。

## 4. 状态
- 全局：空闲 / 备份中 / 已暂停 / 等待中（原因）。等待原因持久化。
- order：待传输 / 传输中 / 已确认 / 失败 / 用户跳过 / 源已删。无暂停、无版本已变、无因范围取消。
- 旧版本的“传输中”（中断期间照片被编辑，导入 hash 对不上）→ 直接舍弃：改“源已删”+ `cancel_tuple`。已确认的旧版本保留。

## 5. 用户操作
- 暂停：只允许在备份中。写暂停标志 → `flow.suspend`（同步、不可取消、限时约 3 秒）→ 退出循环 → 释放 FGS。
- 暂停中只能：继续（回到入口，续传）或 取消剩余。
- 取消剩余（只在已暂停时可用，是否在“等待中”也可用待确认）：一个事务把当前待办全部写进跳过名单、传输中/待传输改用户跳过 → `cancel_tuple` → 清除暂停标志 → 空闲。边界 = 弹窗显示那一刻。
- 恢复已跳过：从跳过名单移除 → 待办现算自然包含。
- 暂停期间的任何变化只改意图，继续后待办现算。

## 6. 中断与失败
- FGS 被收、断网：`flow.suspend`，order 保持传输中；全局等待中。
- onLost 立即判路径失败；连着 3 分钟无新字节判路径失败；15 秒无连接先问桌面状态。
- 路径失败：不计次，挂网络变化回调 + 3 次间隔 10 分钟探测（每次就是一次触发）。
- 后台 FGS 被拒：全局等待中，下次触发照常重试（不再持久卡死到回前台）。
- 单张失败：当场重试 1 次 → 失败；兜底对账重试 1 次，有上限。
- 对端失败：`storage_failed` + `materialize_*`，带具体原因回手机显示，退出循环不计次。
- 桌面半截：超过 3 天未续传清掉；不残留垃圾 order。

## 7. 桌面健康
- 探测回复带：剩余空间、照片库可写、索引库正常。不健康 → 不申请 FGS，等待中（具体原因）+ 桌面系统通知。
- 剩余空间 < 5GB 预警（固定阈值）；offer 时按单张大小预检，放不下当场拒绝。

## 8. UI
- 待备份 = 待办大小（现算、精确、只有一个来源）。进度 = 本轮已完成 /（本轮已完成 + 待备份）。
- 英雄区结构不变；“继续”按钮只看暂停标志。
- 失败先不发通知（留注释待分类）；有通知权限才发。
- 新增文案（已暂停、各等待原因、桌面空间不足、低空间预警）改前列给用户确认。

## 9. 分批
- 第 0 批（和模型无关，立即）：suspend 替代 cancel；hash / presence 挪到 FGS 之后；每轮一条订阅（无界缓冲、按 tuple 过滤）；FGS 被拒不卡死；取消边界；计数加范围；onLost 立即判定；错误重新分类；`materialize_*` 对端失败；已有 order 提交不推进 G（先补测试）。
- 第 1 批：引用导入（真机验证路径可读 / 字节一致）；桌面健康与空间预检。
- 第 2 批：三层模型（跳过名单表、一次传输一行、带数据保留的迁移 + 迁移测试、按优先级取件、现算待办、UI 全局状态、暂停/取消状态机）。
- 真机实验：Android 15 开机后台启动 dataSync FGS；引用导入 E6/E7。基准：10 万张实测（进行中）。
