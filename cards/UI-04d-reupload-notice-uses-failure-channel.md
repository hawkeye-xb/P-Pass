# UI-04d 重传通知挂在「照片备份失败」渠道下，分类名不对　级别 L2

> ⬜ 状态：未开工（2026-09-07 从 UI-04 拆分——原卡混了四个独立缺陷，按用户
> 要求"一个任务一条"拆开，本卡只管这一条）
> 级别：L2 · 阻塞：无

## 问题

`MOB-37` 实施时发现：重传告知的系统通知复用了 `FAIL_CHANNEL_ID`，而那个渠道
对用户显示的名字是**「照片备份失败 Backup failed」**。于是「正在把照片重新传
回来」这条**正常进展**的通知，出现在一个叫「失败」的分组里——用户在系统通知
设置里看到的分类是错的，想单独关掉某一类也做不到。

这是 `MOB-29` 的遗留（当时只有失败通知一个渠道）。

## 期望行为

重传告知有自己的通知渠道（名字表达「进展」而不是「失败」），用户能单独
关掉它而不影响失败通知。

## 验收标准

- [ ] 重传告知有自己的通知渠道，渠道名不含"失败"字样
- [ ] 用户可在系统通知设置里单独关闭重传告知渠道，不影响失败通知渠道

## 范围

- 只准动：`apps/android/.../ui/`（通知渠道定义）、`res/values*/strings.xml`
- 不准动：重传告知**触发条件**（`MOB-29`/`MOB-37` 的判定逻辑）

## 阻塞与依赖

无。
