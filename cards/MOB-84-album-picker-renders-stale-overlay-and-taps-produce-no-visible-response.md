# MOB-84 相册选择页渲染错乱：设置开关残留叠加 + 点击无响应（L1）

> ⬜ 状态：未开工 · 真机复现于 2026-09-16 NET-14 真机验证同一轮会话
> 级别：L1（阻断用户发起备份的可见 UI bug,不是数据安全问题) · 阻塞：无

## 问题

2026-09-16,三星真机重新配对后,在相册选择页勾选相册并点「开始备份」,
无任何反应,需要强退重开才发起传输;随后清理 App 重开又出现明显卡顿;
传输中一度停在 33/37（后自行追完,未卡死,不属于本卡)。

`adb logcat -v threadtime` 现场截图显示:

- 相册选择页渲染错乱:设置页的开关控件残留叠加在相册网格卡片上;
- 点击相册卡片无任何视觉反应,但 `InputDispatcher`/`ViewPostIme` 记录
  触屏事件确实送达了 Activity——**点击被系统收到,但界面状态没有更新**,
  是真实可复现的渲染/状态同步 bug,不是"没点中";
- 与相册数量和顶部总数不一致同时出现（例如"2 个相册"对应
  "0/1 张已回家"),说明这批异常可能同源。

## 期望行为

相册选择页任何时候都不应残留其他页面（设置页)的控件;点击相册卡片必须
有对应的可见状态变化（勾选/取消勾选高亮),不允许"点击送达但界面装死"。

- [ ] 根因定性:是 Compose 状态未随重组更新,还是导航返回栈复用了旧

      真红。

- [ ] 真机回归:按取证路径重复操作,确认相册选择页不再残留其他页面控件、
      点击必有可见响应。
