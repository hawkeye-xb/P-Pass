# UI-03 手机端删掉照片页/设置页的顶部大标题　级别 L3

> 🟡 已合并，等真机验收。**对设计稿 layout-v1 的有意偏离，不是漏做。**

## 用户裁决（2026-08-21 真机）

「mobile 端照片和设置页面，顶部有必要有几个大字吗？【全家的照片】【设置】，
是否可以删除了，占位置还没有什么意义。」

## 为什么这个偏离是对的

底部 tab 已经写着「照片」「设置」——30sp / 28sp 的 serif 大标题是**同一句话
说第二遍**，而且吃掉手机上最金贵的首屏纵向空间（照片墙的第一行、英雄卡的
三元组都被往下推了约 68dp / 42dp）。

桌面端不同：那边窗口大、标题承担的是「你现在在哪一页」的导航功能。手机上这
个功能已经由 tab 承担了。

## 改动

| 文件 | 原来 |
|---|---|
| `PhotosScreen.kt` | `photos_title`「全家的照片」30sp serif，`padding(24,18,24,10)` → 换成 `Spacer(8.dp)` |
| `HomeScreen.kt` | `tab_settings`「设置」28sp serif + `Spacer(14.dp)` → 整块删除（Column 自带 14dp 顶部内边距，英雄卡不会贴边） |

`photos_title` 这个 string 资源**保留**（en/zh 对称），只是不再渲染——桌面端
和将来可能的顶栏还用得上，删了会让 i18n 对称测试和翻译文件白掉一条。

状态栏安全区由 `PPScreen` 的 `safeDrawingPadding()` 负责，与标题无关，删标题
不会顶到状态栏。

## 设计稿偏离登记

`docs/design/2026-08-05-layout-v1/` 是 UI 唯一基准，其中：

- 照片页：标题单独站着（2026-08-17 已经按用户反馈删掉过副标题「N 张 · 已去重」）
- 设置页：T-083 目标 1「仅『设置』28px serif，无副标题」

本卡**推翻这两条中的标题本身**。设计稿要跟着改，否则下一次 UI 走查会把这里
判成「未实现」。⚠️ 待办：更新设计稿或在设计稿里标注此偏离。
