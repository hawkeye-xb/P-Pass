# AUDIT-03 审计合同 v1：Case Matrix 与可信边界（L2）

> ✅ 状态：设计已收口 · 当前节点：Case Matrix 与可信/保留/访问边界已定；实现前置已转入 AUDIT-04
> 级别：L2 · 阻塞：无
> 设计矩阵：[中文 Case Matrix](../docs/design/2026-09-10-audit-contract/case-matrix.zh-CN.md)

## 问题

AUDIT-01 验证了手机 ledger → outbox → Desktop 的可靠投递，但当前事件集合把技术事件与可追溯业务事实混在一起。AUDIT-02 试图先修活动文案，被否决：活动记录必须从正确的审计合同派生，不能反过来定义审计。

## 期望行为

先确定 P-Pass 审计应能证明的业务事实：操作、对象证据、用户/安全决定、审计自身；监控与网络技术事件不进入长期审计。活动记录以 `【本地】`、`显示名称 · #短指纹` 和一句完整结果作为投影，点开后才能审查合同证据。

## 验收标准

- [x] 当前 P-Pass 范围的配对、操作、对象证据、对账、外部删除、恢复决定、审计自身 case 均列入 Matrix；每项写明持久事实、活动文字、详情问题与明确排除项。
- [x] 已定规则：不强制命名本地 Desktop，当前本机显示 `【本地】`；远端设备显示 `名称 · #短指纹`；活动摘要与审计详情分层；连接/路径/重试不进审计。
- [x] 已裁决：本机支持级追溯、数据来去均随库保留、【本地】用户可查详情、不新增审计导出。
- [x] 已由 AUDIT-04 承接：基于本 Matrix 重写审计数据合同、存储模型与新的失败 case；AUDIT-01 当前事件 schema/投影不作为最终合同。

## 范围

- 只准动：本卡、`docs/design/2026-09-10-audit-contract/`、`docs/QUEUE.md`、后续由本卡派生的审计设计/实现卡。
- 不准动：Android/Rust/Desktop 生产代码、AUDIT-01 的 outbox、NET/TEL/OBS、现有备份数据或 receipt。

## 阻塞与依赖

无。可信等级、保留、详情访问及导出边界已在 Case Matrix 固化；后续将从 Matrix 推导正式数据合同、对象 tombstone 与失败 case，不重开已定表达规则。
