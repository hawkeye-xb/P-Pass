## 已定业务原则

```text
一条核心处理管道
+ 一本长期有效的手机本地逻辑账本
= 前台、后台唤醒、触发器与传输都遵守同一份事实。
```

- 用户 `Pause` 是长期命令：杀 App、重启、网络恢复和后台唤醒均不能解除；只有 `Continue` 可解除。
- Wi‑Fi、电量或 Desktop 不可达属于条件等待；条件恢复时可自动继续，且不消耗失败预算。
- 触发器只表达“可能有新照片”；相同触发合并。发现器按水位增量发现，消费者严格一张一张处理。
- 一张照片只有在 Desktop **完整接收、验证、可靠保存，并明确确认本地拥有**后才是 `CONFIRMED`。
- 一旦 `CONFIRMED`，随后改范围、取消本轮或手机重启都不能否定该完成事实。
- P-Pass 是单向备份：Desktop 外部缺失只记为待用户决定，不自动补传，也不删除手机原图。

## 逻辑账本

下列是逻辑事实分类，不预设存储介质：小型用户配置、队列账本与传输 partial 可使用不同实现，只要共同满足本节不变量。

| 类别 | 保存的事实 | 生命周期 |
|---|---|---|
| 用户配置与范围 | 自动备份开关、Wi‑Fi/电量条件、已选相册 | 换 Desktop 后保留 |
| 用户控制 | `PAUSED_BY_USER` | 仅 Continue 改变 |
| 发现水位 | 已可靠处理到的媒体位置；新增相册的补扫请求 | 手机本地备份历史 |
| 单张队列与完成凭据 | 顺序、当前项、结果、失败信息、Desktop 完成事实 | 当前 Desktop 的传输历史 |
| 取消本轮 | 取消是否进行、取消扫描进度、该轮取消项 | 可恢复/可丢弃 |
| 当前配对与传输归属 | 当前 Desktop、有效传输归属与 partial 所属关系 | 换 Desktop 时清理 |

### 不变量

```text
发现水位前移
= 该页照片已可靠入待传列表，或已可靠标记取消。

Desktop 完成凭据
= 已完成事实；后续控制操作不能覆盖它。

取消本轮活动中
= 进入待传列表的任何项都直接取消，不得上传。

换 Desktop
= 保留用户配置；清旧 Desktop 的队列、水位、取消轮、断点与进行中传输数据。
```

## 控制语义

| 状态/动作 | 含义 | 谁可恢复 |
|---|---|---|
| `PAUSED_BY_USER` | 用户明确要求停止消费队列 | 仅用户 Continue |
| `WAITING_FOR_CONSTRAINTS` | Wi‑Fi、电量或 Desktop 条件暂不满足 | 条件恢复自动继续 |
| `RETRYING` | 单张出现可重试错误 | 重试策略 |
| `DISABLED` | 自动备份整体不再接收自动工作 | 用户重新开启 |
| `Cancel Current Round` | 在 Pause 后取消本轮全部未完成待传项 | 显式 Restore 才重新准入 |

## 范围、取消与配对

### 修改范围

- **增加相册**：当前队头和当前窗口不变；新增相册做历史补扫，结果追加到后续窗口。
- **减少相册**：新范围生效后，未获 Desktop 完成凭据的旧范围项取消；已获完成凭据的项仍是 `CONFIRMED`。

### 取消本轮

```text
Pause
→ Cancel Current Round
→ 取消当前已发现未完成项
→ 按 500 项分页继续发现本轮其余候选，并直接取消
→ 取消过程中入待传列表的项也直接取消
→ 本轮待传列表为空，原子结束取消轮
→ 之后才入队的项属于下一轮
```

`Restore Cancelled Round` 重新准入该轮取消项；`Discard Cancelled Round` 关闭快捷恢复入口，不影响后续新增照片。

### 换 Desktop

```text
保留：用户配置与相册选择
清理：旧队列、发现水位、取消轮、partial、运行中传输与旧 Desktop 归属
结果：新 Desktop 从新的传输历史开始
```

## 开发前门禁

下一阶段不是重新讨论业务，而是把以上规则转换为实现卡中的失败测试与本地原子提交边界。优先顺序：

```text
手机逻辑账本与发现原子提交
→ 严格队列消费者与完成凭据
→ Pause / Continue / Cancel Current Round
→ 原生传输、partial 生命周期与重启恢复
→ 调度与 UI
```
