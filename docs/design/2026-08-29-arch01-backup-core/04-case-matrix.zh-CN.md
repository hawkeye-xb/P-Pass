# ARCH-01 失败 Case Matrix 与验收矩阵

> 中文主档 · 2026-08-29 立档 · 2026-09-23 逐张循环模型  
> 业务规则来源：[ARCH-01](../../../cards/done/ARCH-01-backup-core-flow-queue-design.md) · [#413](https://github.com/hawkeye-xb/P-Pass/issues/413) · [设计归档](README.zh-CN.md)

本文件是生产实现前的测试合同。每一项先写成会失败的自动行为测试，确认失败原因正确后才写最小实现。它不引入新产品语义，也不决定表结构或 UI。

每行的读法：**Given + When = 触发条件**；**Then = 期望**；**反证 = 去掉哪条保护，这条测试就必须变红**；**真机验收 = 验收人的操作步骤与可见结果**。各行的拍板依据见 #413 的两条裁决评论（#415 / #416 遗留点）。

## 三层证据

| 层 | 目的 | 谁执行 |
|---|---|---|
| 合同测试 | 用公开命令和账本投影锁定业务规则 | 开发自动执行 |
| 故障/反证测试 | 模拟崩溃、迟到回执和并发；移除保护时必须变红 | 开发自动执行 |
| 真机验收 | 验证 UI、系统唤醒、真实连接与用户可见结果 | 验收人 |

真机验收只使用独立测试相册；不对真实照片库做写入、删除或破坏性操作。

## 执行顺序

```text
O order 与差集
→ D 发现
→ C 逐张循环与消费控制
→ E 完成凭据
→ X 取消与改范围
→ P 换 Desktop
→ 原生传输 adapter、调度、UI
```

## P0：order 与差集

| ID | Given | When | Then | 反证 | 真机验收 |
|---|---|---|---|---|---|
| O-01 | 范围内新拍一张 #N，其 generation 大于 G；#N 没有 order | 内容触发，循环启动 | 快路径 `GENERATION_MODIFIED > G` 查到 #N；算 BLAKE3 → 建 order → 传输 → `CONFIRMED` | 去掉快路径查询（只靠慢路径）时，#N 在触发后的这次循环里不被传，必须失败 | 测试相册里拍一张，保持 App 在前台，观察它在不打开设置、不等 5h 的情况下变为已备份 |
| O-02 | #M 在范围内、无 order，但 generation 不大于 G（G 超前或提示丢失导致快路径漏掉） | 慢路径运行（App 打开 / 5h 兜底） | 按 `_id` 归并比对发现 #M 缺 order；算 hash 后进入传输，最终 `CONFIRMED` | 让慢路径只处理 `> G` 的行时，#M 永远不传，必须失败 | 自动测试为主（快路径漏照片难以手工制造） |
| O-03 | #K 已 `CONFIRMED`，hash=H；MediaStore 重建后 #K 的 `_id` 变成新值，内容不变 | 慢路径（`getVersion` 变化触发全量对账） | 新 `_id` 算出 hash=H，命中已有 order：只更新 `(_id, 版本) → H` 映射，不建新传输，传输次数为 0 | 去掉「hash 已存在则只更新映射」时会重传，必须失败 | 自动测试为主；真机只核对大规模媒体库变化后首页已备份数不回落 |
| O-04 | #K 已 `CONFIRMED`，hash=H1 | 用户编辑 #K 并保存，内容变为 H2 | 按新版本传：新建 H2 的 order 并传输至 `CONFIRMED`；H1 的 order 仍为 `CONFIRMED` | 只按 `_id` 判重（不看版本 / hash）时 H2 不传，必须失败 | 在测试相册编辑一张已备份照片（如旋转或裁剪），它再次被传到 Desktop |
| O-05 | #S 有未完成或 `FAILED` 的 order，原文件已从手机删除 | 慢路径归并比对 | #S 记为 `SKIPPED_SOURCE_MISSING`；不再尝试传输，也不重试。`CONFIRMED` 的 order 不改写，只打 `source_missing` 标记；原图重新出现时 `SKIPPED_SOURCE_MISSING` 恢复为可传、标记清除 | 让源缺失的 order 保持可重试时，每次慢路径都会重试并失败，必须失败 | 测试相册里一张待传照片先在系统相册删除，再打开 App；该照片不再出现在待传进度里 |
| O-06 | 范围内有 N 张没有结局 | 用户确认「取消剩余 N 张」，随后慢路径运行 | 同一事务写入 N 条 `SKIPPED_BY_USER`；慢路径对这 N 张既不补传也不重试 | 取消只退出循环、不写 order 时，下一次慢路径把 N 张全部补传，必须失败；让慢路径把 `SKIPPED_BY_USER` 放进补传列表时也必须失败 | 测试相册放 5 张新照片，传出第 1 张后点「取消剩余 4 张」，杀 App 重开并等后台唤醒，这 4 张始终不传 |
| O-07 | #R 的最后一块已到达，Desktop 发出完成凭据 | 手机处理凭据；故障注入：写入过程中崩溃 | order=`CONFIRMED`、hash 映射、G 的推进在同一次写入中生效；崩溃后要么三者都在，要么都不在（此时重启再传一次，Desktop 按内容去重） | 把 `CONFIRMED` 与映射拆成两次写入时，能观察到「`CONFIRMED` 但无映射」或「有映射但未确认」，必须失败 | 自动测试为主 |
| O-08 | #K 已 `CONFIRMED`，Desktop 上该文件被外部删除，手机原图仍在 | 慢路径分页询问 Desktop 存在性 | #K 标记为补传，下一次循环按取件顺序 ② 自动重新传输至 `CONFIRMED` | 去掉 Desktop 存在性检查，或发现缺失后只记录不补传时，必须失败 | 在专用测试副本上从 Desktop 删除一张已备份照片，打开 App；它被自动重新传回 |
| O-09 | #F 为 `FAILED` | 慢路径运行两次，#F 每次重试都失败 | 每次慢路径只重试一次；仍失败保持 `FAILED`，不在同一次慢路径里循环重试 | 去掉「每次慢路径一次」的上限时出现无穷重试，必须失败；去掉慢路径重试时 #F 永远不再尝试，也必须失败 | 自动测试为主 |
| O-10 | 慢路径跑完 | 对范围内每个 `_id` 查询状态 | 每张要么有结局 order，要么有未完成 order 在待传，要么是本次发现的新照片；不存在「说不清被跳过还是被漏掉」的照片 | 用区间记录代替逐张 order 时，被编辑后 generation 改变的照片无法回答状态，必须失败 | 自动测试为主 |
| O-11 | #K 已 `CONFIRMED`，Desktop 缺失，手机原图也已删除 | 慢路径 | #K 保持 `CONFIRMED`（带 `source_missing` 标记），只记审计 `unrecoverable`，不补传、不做 UI | 把缺失当作可补传（插入待传行）时会去传一张不存在的原图，必须失败 | 自动测试为主 |

## P0：发现

| ID | Given | When | Then | 反证 | 真机验收 |
|---|---|---|---|---|---|
| D-01 | 已有 g=10、g=11 两张待传；新拍 g=20 | 循环取下一张 | 顺序为 10 → 11 → 20，新照片不插队 | 把新触发带来的 URI 放到队首时，顺序变成 20 在前，必须失败 | 自动测试为主 |
| D-02 | 循环正在传 #1 | 连续到达 3 次内容触发 | 只有一个循环在跑；触发带来的 URI 合并，不启动第二个循环，不重复申请 FGS | 每次触发各起一个循环时，出现并发传输或多次 FGS 申请，必须失败 | 传输中连拍 3 张测试照片，通知栏只有一条 FGS 通知 |
| D-03 | 循环正在传 #1；期间新拍 #N | #1 完成，循环取下一张 | 快路径取到 #N，在同一次循环内传输，不需要额外触发 | 循环只消费启动时的快照（物化队列）时，#N 要等下一次触发，必须失败 | 传输一张大文件时拍一张新照片，它在同一轮通知进度里被传出 |
| D-04 | G 丢失或被清零；多数照片已 `CONFIRMED` | 快路径查询 | 已有结局 order 的照片被 order 过滤，不重传；没有照片丢失 | 快路径跳过 order 过滤时会重传已确认照片，必须失败 | 自动测试为主 |
| D-05 | 上次对账记录的 `getVersion` 为 V1 | MediaStore 版本变为 V2，任一触发到来 | 执行一次全量对账（慢路径全部 5 步）并记录 V2 | 忽略 `getVersion` 变化时，MediaStore 重建后的 `_id` 变化无人处理，必须失败 | 自动测试为主 |
| D-06 | 10 000 张照片中只有 3 张新增或版本变化 | 慢路径归并比对 | 只读 `_id`、修改时间、大小三列；只对这 3 张算 BLAKE3 | 对未变化的照片也算 hash 时，hash 调用次数大于 3，必须失败 | 自动测试为主；耗时实测见 #413「待实测」 |
| D-07 | 设备 API 26–29（无 `GENERATION_MODIFIED`）；或有多个外部卷 | 快路径 | API 26–29 用 `DATE_MODIFIED > G` 作加速提示，漏掉的由慢路径兜底；G 按卷分开存、按卷查询 | 快路径只查一个卷时，其它卷上的照片不传，必须失败 | 插 SD 卡的机器上，SD 卡测试相册里拍一张，它被正常备份 |

## P0：逐张循环与消费控制

| ID | Given | When | Then | 反证 | 真机验收 |
|---|---|---|---|---|---|
| C-01 | #18 正在传输，后面还有照片 | 用户 Pause | 退出循环；释放 FGS 与 wakelock；#18 的 order 保持可续传，partial 保留；下一张不开始；不做任何保活 | 暂停后仍持有 FGS，或下一张开始时，必须失败 | 传输中点暂停：FGS 通知消失，没有下一张开始 |
| C-02 | 已 Pause | App 重启、后台唤醒、网络恢复、重复触发、手动触发 | 仍 Pause；worker 检查到暂停即结束，不申请 FGS，不传输 | 任一触发跳过暂停检查、或能清除暂停时，必须失败 | 暂停后杀 App 重开、切前后台、开关 Wi‑Fi，仍显示暂停，通知栏无 FGS 通知 |
| C-03 | 已 Pause，#18 的 order 未完成，另有慢路径标记的补传项和快路径新照片 | 用户 Continue | 取件顺序：① 先续传 #18 → ② 补传或重试项 → ③ 快路径下一张 | 打乱取件顺序（例如先取快路径新照片）时，#18 不是第一张，必须失败 | 暂停一张传到一半的照片后 Continue，进度从这张继续 |
| C-04 | 未 Pause；仅 Wi‑Fi 开启但当前是移动网络（或电量低、今天额度耗尽、Desktop 不可达） | 任一触发 | worker 内检查不通过：不申请 FGS；登记对应唤醒（网络变化回调 / 不可达后 3 次间隔 10 分钟的探测 / 条件约束任务 / 额度耗尽则等 App 回前台） | 条件不满足仍申请 FGS，或不登记唤醒导致条件恢复后不自动继续，必须失败 | 开「仅 Wi‑Fi」后切到移动网络：无 FGS 通知；切回 Wi‑Fi 后自动开始传 |
| C-05 | #18 正在传输 | Wi‑Fi、电量或 Desktop 条件丢失 | 退出循环、释放 FGS，登记唤醒；#18 保持可续传，不计入失败；唤醒后自动续传 #18 | 把等待计为失败，或恢复需要用户 Continue，必须失败 | 传输中关掉 Desktop，再打开：自动续传，不出现错误或 Continue 按钮 |
| C-06 | 有 3 张待传，条件都满足 | 一次触发 | 整个循环只申请一次 FGS + PARTIAL_WAKE_LOCK；3 张传完、取不到下一张后释放两者 | 按单张启停 FGS 时申请次数为 3，或循环结束后仍持有，必须失败 | 连续传 3 张，通知栏 FGS 通知不闪烁，传完后消失 |
| C-07 | 循环中，#18 已完成 | 取 #19 前条件已变（例如刚进入暂停或 FGS 已失效） | 每张开始前重检条件与 FGS 有效性；不满足则不开始 #19 并退出 | 只在循环开头检查一次时，#19 在条件不满足下开始，必须失败 | 自动测试为主 |
| C-08 | 后台触发，申请 FGS 被系统拒绝或 FGS 超时 | 同一进程或重启后再有后台触发 | 记下 FGS 受阻事实并退出；App 进入前台前不再调用 `startForegroundService`；进入前台后清除该事实并继续 | 被拒后在后台重复申请（#414）时，必须失败 | 自动测试为主；真机只核对回到前台后自动继续 |
| C-09 | #18 读取失败（单张失败） | 传输 #18 | 立即重试 1 次；仍失败记 `FAILED`，循环继续 #19 | 不重试、无穷重试，或失败卡住后续照片，必须失败 | 自动测试为主 |
| C-10 | #18 连接还在，但 3 分钟没有新的文件字节（`Progress.end_offset` 不前进） | 传输判定 | 主动断开，判为路径失败：#18 保持可续传，退出循环、释放 FGS，不计入单张失败 | 无限等待，或把路径失败记为 `FAILED`，必须失败 | 自动测试为主 |
| C-11 | 15 秒没有 Desktop 来连 | 传输判定 | 询问 Desktop 状态；回答 active 就继续等，不判失败 | 15 秒直接判失败时，必须失败 | 自动测试为主 |
| C-12 | Desktop 明确回报无法保存（`storage_failed`，对端失败） | 传输 #18 | 退出循环、释放 FGS；#18 保持可续传，不计入单张失败次数；等下一次唤醒。`fetch_failed` 按路径失败处理，未知 code 按单张失败处理 | 把对端失败计入单张次数（记 `FAILED`）时，必须失败；不读 code、一律当单张失败时，必须失败 | 桌面磁盘写满后传一张：不出现失败计数，清出空间后下一次唤醒自动传完 |

| X-04 | #18 正在传输 | 用户修改相册范围 | 当场不写任何 order、不扫描；下一次快路径 / 慢路径查询使用新范围。正在传的 #18 让它传完，下一张开始之前再按新范围检查；新增相册当场触发一次慢路径 | 改范围时同步扫描并批量改写 order 时，必须失败 | 自动测试为主 |
| X-05 | #18 传了一半后暂停；#18 所在相册仍在范围内，原文件还在 | 用户 Continue | #18 续传，只补缺失部分 | 恢复时丢弃 partial 从头传时，传输字节数大于剩余部分，必须失败 | 暂停一张大文件后 Continue，进度从原位置继续 |

| X-07 | #18 传了一半后暂停；原文件在系统相册中被删 | 用户 Continue | #18=`SKIPPED_SOURCE_MISSING`；循环取下一张 | 恢复时对已删文件报单张失败并重试时，必须失败 | 暂停后在系统相册删除该测试照片再 Continue，这张不再出现在进度里 |
