# UI-11 Android 顶部安全区与状态栏图标对比度必须真实可见（L1）

> ⬜ 状态：未开工
> 级别：L1 · 阻塞：无

## 问题

2026-09-11 真机观察：App 顶部能隐约看见状态栏图标；在白色背景上图标对比度不足，视觉上像页面没有正确处理顶部安全区或留下了渲染缺陷。

当前代码声称 `PPScreen` 统一处理 edge-to-edge、安全区 padding 与浅/深状态栏图标。因此这不是靠再给某个页面手写一段顶部留白就能宣布完成的问题：必须在真实 Android 状态栏、刘海/打孔区和浅色页面上核实最终像素与内容边界，定位是 inset、system-bar appearance 还是某条页面绕过统一容器。

## 期望行为

所有浅色 Android 页面中，状态栏图标具备系统级清晰对比度，应用内容不被状态栏/显示缺口遮挡，顶部不会出现无意义的额外白条；深色查看器/扫码页反向保持浅色系统图标。安全区规则由统一容器控制，不允许各页各自猜 padding。

## 验收标准

- [ ] 自动化：`PPScreen` 对浅/深背景分别设置正确的 system-bar 图标外观；安全区 inset 只由统一容器消费。
- [ ] 自动化：入口、双 tab 首页、相册选择、onboarding、查看器等页面不绕开统一安全区策略；若有例外须有明确理由和测试。
- [ ] 反证：移除浅色背景的状态栏外观设置，焦点检查必须失败。
- [ ] 真机截图：浅色首页/相册选择/onboarding 与深色扫码/查看器各至少一张，证明状态栏图标清晰、内容未被遮挡、无额外顶部白条。

## 范围

- 只准动：Android `MainActivity` 的 edge-to-edge 配置、`ui/PPScreen.kt` 及直接相关页面容器/测试与卡片证据。
- 不准动：业务状态、照片查看/传输协议、全局设计 token 或每页的业务布局重构。
