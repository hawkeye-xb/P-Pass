# MOB-73 查看本机已备份照片时优先读取本地源（L2）

> ⬜ 状态：未开工
> 级别：L2 · 阻塞：无

## 问题

手机自己已备份到远端的照片，在本机照片墙中再次打开、查看大图、保存或分享时，当前查看器统一经 `TimelineLoader` 向远端读取缩略图/原图。对于仍保留在这台手机相册中的同一内容，这会产生不必要的网络往返、流量和等待；蜂窝网络或 relay 路径下尤为明显。

现有 `AssetMeta.src_device` 已能识别资产是否来自本机；本机 Flow 账本/哈希缓存也已保存内容 hash 与 MediaStore `content://` 来源的本地映射。不得把 Android 的原始路径或 URI 上传到远端元数据：本地来源索引只属于这台设备。

## 期望行为

当资产的 `src_device` 是本机、且本机仍可读取并验证为相同 content hash 的 MediaStore 源时，照片墙缩略图、查看器大图和查看器的保存/分享动作都读取本地字节，不发起远端下载。源不存在、权限失效、无法读取或内容已变化时，诚实回退到现有远端路径；不得用过期 URI 显示错误照片，也不得建立长期原图缓存。

## 验收标准

- [ ] RED→GREEN：给定本机来源、可读 URI 与匹配 hash，缩略图/大图/保存/分享路径均使用本地 resolver，远端 loader/download 调用次数为 0。
- [ ] 自动化：非本机来源、缺失 URI、拒绝读取、或重新校验后 hash 不匹配时，均只回退远端；不会把本地错误文件展示为目标资产。
- [ ] 反证：把本机来源路径改为直接调用远端 loader，焦点用例必须捕获远端调用并失败。
- [ ] 真机：同一台手机备份后不删除原图，断开远端或观察网络请求仍能打开本机照片；删除本机原图后，若远端可达则同一资产按现有远端路径可查看/保存/分享。
- [ ] 资源红线：不把 Android `content://` URI/文件路径写入 daemon、协议 `AssetMeta`、审计或远端数据库；不新增长期原图缓存。

## 范围

- 只准动：Android 本地来源索引/验证、`TimelineLoader` 与照片查看器的本地优先分派、相关 Android JVM 测试。
- 不准动：远端 `AssetMeta` wire schema、daemon 索引/审计、资产归属语义、RET-01 的临时文件清理红线、桌面查看器。

## 阻塞与依赖

无。实现前须先决定复用现有 Flow ledger 的 `sourceRef`，还是在本地维护一张等价的 hash→MediaStore URI 索引；两者都必须只留在本机，并在读取前验证当前内容仍匹配资产 hash。
