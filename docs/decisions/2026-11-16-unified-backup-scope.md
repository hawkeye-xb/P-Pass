# 统一自动备份范围：相册与文件夹同源选择、按拍摄时间过滤

- 状态：已采纳（产品负责人 2026-11-16 确认，[范围定案](https://github.com/hawkeye-xb/P-Pass/issues/1775#issuecomment-6906968617)、[开关与日期补充定案](https://github.com/hawkeye-xb/P-Pass/issues/1775#issuecomment-6907178211)）
- 日期：2026-11-16
- 关联：#1775、#1776、#1777、#1778、#1731、#1762、#1763、#1263、#1323
- 代码基线：`c229c7fa`
- 范围：iOS / Android 的持续自动备份范围；不含单次备份

## 结论

相册与文件夹统一为「备份来源」。同一来源集合、同一时间条件和同一个保存动作决定持续自动备份；范围时间只按「拍摄／创建时间 → 文件修改时间」两级读取，不能再把加入媒体库的时间当作拍摄时间。

已有范围时，自动备份开关只启停，不主动打开范围页；绝对起点日期持久保存，不因开关或进程重启按新的今天重算。文件夹的取消勾选与移除授权是两个不同动作。

继续复用现有 Composite、Flow、内容哈希去重和目录授权，不新增传输、订单或去重机制。

## 背景

#1775 要求把相册和本地目录纳入同一个自动备份范围。当前实现存在以下差异：

1. iOS 相册使用 `PHAsset.creationDate`，缺失时没有修改时间回退；Android 相册范围使用 `MediaStore.DATE_ADDED`，表示加入媒体库的时间，不是拍摄时间。
2. 双端文件夹来源当前只读取修改时间，没有统一的范围勾选和时间过滤。
3. Android 已有 `captureAtMsOf = DATE_TAKEN → DATE_MODIFIED → DATE_ADDED`，用于媒体展示信息；最后一级不符合本次范围规则，不能原样复用为范围时间。
4. iOS `AppModel.applyAutoRuleAccess` 与 Android `MainActivity.applyRuleAccess` 在完整权限下都会进入范围页，即使已有保存范围。这是 #1323 的旧行为，本次改为只启停。
5. iOS `BackupSince?` 与 Android `ScopeRead` 已能区分未保存、全部和绝对起点；不需要重写存值或做数据迁移。

## 决定

### 1. 统一来源模型

- 「备份来源」由选中的相册与选中的文件夹组成；两类来源使用同一个起点日期或「全部」。
- 沿用现有范围存值与文件夹 bucketId：iOS 使用 `folder:<sourceId>`，Android 使用 FolderRegistry 分配的 Long 命名空间。不得另建一套范围订单或传输队列。
- 文件夹卡片代表整个已授权目录及其所有层级子目录。
- 同一内容出现在多个已选来源时按并集处理，桌面继续按内容哈希去重，不重复占盘。

### 2. 范围时间只有两级

每个媒体项目按以下顺序取得范围时间：

1. 拍摄／创建时间；
2. 只有第一项缺失时，才读取文件修改时间。

规则：

- 有拍摄／创建时间时，即使修改时间更早或更晚，也必须使用拍摄／创建时间。
- 起点日期包含当地当天，比较使用持久化的绝对时间戳；「全部」不做时间过滤。
- 两级都缺失时不得伪造时间，也不得再回退 `DATE_ADDED`。沿用「未知时间不进入日期档」的保守语义；「全部」不受影响。
- 文件名、路径、Blackmagic 目录结构和厂商特例都不是时间来源。
- 修改时间仍可组成 `sourceVersion = modifiedAt:size`，用于内容版本识别；这与范围过滤是两个独立用途。

平台实施对齐：

| 来源 | 第一级 | 第二级 |
|---|---|---|
| iOS 相册 | PhotoKit `creationDate` | 系统可读取的原始文件修改时间 |
| Android 相册 | `MediaStore.DATE_TAKEN` | `MediaStore.DATE_MODIFIED` |
| iOS 文件夹 | 图片 EXIF / 视频创建时间元数据 | `contentModificationDate` |
| Android 文件夹 | 图片 EXIF / 视频容器元数据 | SAF 文件 `lastModified` |

元数据读取失败只表示该项目时间未知，不能当作文件已删除，也不能改变缺席判定的可信度。

### 3. 未保存、全部、具体日期是三态

- **未保存**：从未成功保存范围配置；只有这一状态才主动进行首次范围引导。
- **全部**：用户已保存「全部」，不是未保存。
- **具体日期**：保存一个绝对起点时间戳，起点日期包含当天。

首次选择日期档时计算一次当地当天零点并保存。此后：

- 自动备份关闭再打开，不重新计算起点；
- 杀进程、重启或再次打开范围页，都读取原绝对起点；
- 已保存的日期档再次保存，仍保留原起点；
- 只有从「全部」改回日期档，或未保存状态首次选择日期档，才取当时当地当天零点；
- 不写数据格式迁移，不把旧的「全部」误读成未保存。

### 4. 范围页一次保存全部修改

页面结构固定为：

```text
备份范围
├─ 拍摄时间：某日期起（含当天）/ 全部
└─ 备份来源
   ├─ 相册卡片
   ├─ 文件夹卡片（含子目录）
   └─ 「＋ 添加文件夹」动作卡片
```

- 相册与文件夹卡片使用一致的选中表现；添加文件夹是动作，不显示选中状态。
- 添加文件夹返回后生成默认选中的卡片，但只进入本次编辑暂存，不得绕过保存直接产生备份待办。
- 相册、文件夹和时间条件通过同一个「保存」原子生效；未保存返回不改变已生效范围。
- 范围页不创建相册，不加入单次挑选具体文件的入口。

### 5. 开关与导航分离

- 已有保存范围时，自动备份 off/on 只改变启停状态，不主动导航到范围选择页。
- 无存值或首次配置时，才主动引导进入范围选择。
- 用户主动点击「备份范围」始终可以查看和修改。
- 权限申请、有限授权与拒绝的既有处理不因本条改变；这里只取消完整权限且已有范围时的强制跳页。
- 开关重新打开后按既有唤醒机制启动一轮备份，不依赖用户再次保存范围。

### 6. 取消勾选与移除授权不同

- **取消勾选**：只把文件夹移出备份范围，保留授权和卡片；重新勾选后可继续使用。
- **移除**：单独确认后移除卡片，并释放 P-Pass 保存的目录授权；不得删除手机原文件夹、素材或桌面已确认副本。
- 新增卡片未保存前不得进入持续备份；授权保存失败不得产生可用来源。

### 7. 发现、递归与去重沿用现有主链

- FolderMediaSource 继续完整递归枚举并遵守现有可信缺席契约；范围过滤不能破坏分页顺序或把枚举失败当空集。
- 父子目录使用同一时间规则，不允许只过滤当前层。
- PhotoKit / MediaStore 与 Folder 继续经 Composite 合并，Flow 每次处理一件。
- 不改 `MediaDetails` 的传输语义、桌面 ingest、手选 Picked、内容哈希去重或桌面保留规则。

### 8. 实施边界

- iOS 执行卡 #1777 不命中当前核心名单，可依据 #1775 产品定案实施；本文作为共同口径参考。
- Android 执行卡 #1778 命中 `backup/order/**`，其 PR 必须引用 origin/main 上已采纳的本文，才能实施。
- 双端各自完成「范围页 + 来源装配 + 时间过滤 + 回归测试」，不得先合一个只有界面、没有统一行为的半成品。

## 理由

本质上要保证的是：用户选择的范围和时间规则稳定、可解释，不因来源类型、开关或日期变化而悄悄改变。

标准做法是使用平台媒体元数据：PhotoKit / MediaStore 提供相册事实，图片 EXIF 与视频容器元数据提供拍摄时间，文件系统修改时间只作缺失回退。范围配置作为显式持久状态管理，系统目录授权继续由 security-scoped bookmark / SAF 持有。

本方案不从文件名猜时间，不用 `DATE_ADDED` 冒充拍摄时间，也不为单一相机厂商增加分支。双端只在平台 API 上分叉，业务判定保持一致。

## 后果

- Android 中「今天才加入媒体库的老照片」不再因 `DATE_ADDED` 被纳入日期档，这是有意修正。
- 文件夹需要读取媒体元数据，扫描成本会增加；实现应避免为范围过滤读取完整文件，并保留失败与未知时间的可判定日志。
- 已有范围的用户重新打开自动备份时不再被强制带到范围页；需要修改时必须从明确的「备份范围」入口进入。
- 双端需要补充真实 Blackmagic 原视频与 Proxy 的元数据实证，不能仅凭构造测试宣称兼容。

## 备选

1. **保留相册与文件夹各自规则**：实现较小，但同一页面产生两套语义，排除。
2. **继续使用 `DATE_ADDED`**：查询简单，但把收录时间误当拍摄时间，排除。
3. **文件夹只按修改时间**：无需解析媒体元数据，但有拍摄时间时会发生误纳或误排，排除。
4. **每次打开自动备份都进入范围页**：能提醒范围，却反复打断已有配置的用户，排除。
5. **动态解释「从今天起」**：文案简单，但重启或跨天后范围会自行变化，排除。

## 验收

双端执行卡至少覆盖：

1. 同页选择相册与文件夹，一次保存生效；未保存返回不改变原范围。
2. 拍摄新／修改旧必须纳入；拍摄旧／今日加入或修改必须排除；起点当天包含。
3. 拍摄时间缺失才回退修改时间；两级都有时不得回退，两级都无时不得使用 `DATE_ADDED`。
4. 父子目录同规则；真实 Blackmagic 原视频与 Proxy 记录并验证实际元数据。
5. 未保存、全部、具体日期三态可辨；off/on 与杀进程重启后绝对起点不波动。
6. 有保存范围时 toggle 不跳页；无存值才首次引导；主动进入范围页可编辑。
7. 取消勾选保留授权，移除确认后释放授权，原素材与桌面副本不删除。
8. 多来源同内容不重复占盘，Picked 行为不变。
9. 新增或修改的判定先有能判红的测试；修复后转绿，撤销修复重新变红。
10. 中英两语及双端真机验收按 #1775 执行。

## 非目标

- 单次备份、系统文件多选、手选批次与结果展示。
- 创建相册、服务器相册同步。
- 桌面已有内容的保留规则调整。
- 新传输协议、新去重机制或通用文件备份。
